**Требования:** R01, R02, R03, R06i
**Зависит от:** —
**Зона:** `skills/autopilot/tools/run_log.py` · `skills/autopilot/tools/ap.py` · `skills/autopilot/phases/dashboard-template.html` · `skills/autopilot/prompts/executor.md` · `docs/autopilot/measuring-cost.md` · `AGENTS.md` · `tests/test_spend_accounting.py` · `tests/test_run_log.py` · `tests/test_ap.py` · `tests/test_dashboard_*.py` · `tests/test_audit_docs.py`
**Волна:** 1
**Ревью:** нет
**Модель:** обычная
**Класс:** обычный
**Риск:** обычный
**Причина класса:** новая логика учёта в двух файлах плюс колонка в шаблоне, около 400 строк с тестами; по образцу существующих `compute_spend` и `usage_from_transcript`
**Объём:** 400

## Что должно заработать

`report-run` и «Подробности» дашборда показывают кэш субагентов и долю попаданий; строка «оркестратор» показывает расход главной сессии за время прогона; исполнитель запускает проверки с коротким выводом. Подробные истории и решения — `spec.md` (R01.1–R01.5, R02.1–R02.6, R03, R06i).

## Из брифа, дословно

> «Сделай отдельную сборку по оптимизации расхода»
> «ок, все три» (ничего не брать из прошлой сборки; составную команду отложить; читать из журнала главной сессии только суммы токенов)

## Разделы спецификации

Решение, истории R01–R06i, Решения по реализации, `interfaces.md` (границы).

## Критерии приёмки

- [ ] `compute_spend` на строках с `cache_read`/`cache_write` отдаёт эти суммы и `hit` в `byRole`, `byModel`, `byTicket`; `tokens` остаётся вход+выход; строка без полей кэша, с `True`, `-5` или `"7"` не ломает расчёт и даёт 0; без знаменателя `hit` равен `None`
- [ ] `run_log.usage_by_model` на фикстурном JSONL (ответы двух моделей, повтор одного `message.id`, строка `isSidechain: true`, строка до `since`, испорченная строка, строка без `usage`) возвращает ожидаемые суммы по моделям; нечитаемый путь даёт `None`; файл в десятки тысяч строк читается построчно
- [ ] `ap.py spend-orchestrator --transcript <фикстура>` пишет в `run-log.jsonl` строки `role=orchestrator` с числами и моделью и без текста сообщений; второй вызов не удваивает сумму в `compute_spend`; без `--transcript` и без найденного журнала — одна строка «расход оркестратора не найден: …» и код выхода 0
- [ ] `ap.py finish` в харнессе тестов не падает при отсутствии журнала сессии и при наличии (`CLAUDE_CONFIG_DIR` указывает во временную папку)
- [ ] `report-run` печатает таблицу «Кэш по ролям» с долей попаданий, а без `--share` ещё и таблицу по профилям (`agent_type`); `--share` не содержит имён прогона и профилей
- [ ] В шаблоне таблицы «Расход» получают колонку «Кэш, %» (русский и английский текст); jsdom-тест на `spendTable` с `hit` и с `null`
- [ ] `prompts/executor.md` содержит правило тихого вывода и по-прежнему требует код выхода (тест на обе фразы)
- [ ] `docs/autopilot/measuring-cost.md` описывает новые числа и их границы (оркестратор — по умолчанию самый свежий журнал папки; кэш не стоимость), `AGENTS.md` — одна строка; счётчик тестов обновляется отдельным коммитом, не в этом
- [ ] `python -m unittest discover -s tests -p test_spend_accounting.py`, `-p test_run_log.py`, `-p test_audit_docs.py` и `-p test_dashboard_*.py` зелёные; полный прогон не нужен: его делает оркестратор
