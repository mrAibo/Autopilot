## Известные баги

- Opus: `opusAgents` подписан (`agentsSig`), но guard подпись не сверяет; подпись подтверждения не привязана к прогону; в нестрогом прогоне при планировании она не проверяется; `opus status` пишет «подпись: есть» без проверки; в строгом прогоне без ключа повторный `approve` говорит «подпись неверна» вместо «нет ключа», без `gate_sign.py` — `ImportError` (`claude_agent_guard.py:30-39`, `ap.py`)
- `--by-user` ничем не проверяется: оркестратор технически может подставить строку; открытые строки манифеста снимаются `finish --by-user`, а R24 говорит «снимает только пользователь» — противоречие в спеке
- Хук git: `bash --login -c`, `cmd /c`, `powershell -Command` с `git stash` проходят; слово git ищется не только в позиции команды — ложный отказ на `git log --grep git stash` (`claude_agent_guard.py`)
- Журнал: пути `/tmp/`, `/mnt/c/`, UNC не заменяются на `[path]`; `reason` сброса без шаблона; `tests --seconds` принимает nan/inf; сброс таска может записаться дважды
- `claude-version`: печатает весь список проблем даже для версии, где часть исправлена; не разбирает точку после версии; не находит `claude.cmd` на Windows
- Нет теста на новый отпечаток и CRLF для `codex_dispatch.py`
- «Итог»: колонки «ревью» и «приёмка» выводятся из статуса таска, а не из данных ревью; строка тестов зелёная даже при упавших тестах
- «Обзор»: Гант показывает 8 строк (случай ≥9 тасков не покрыт); «обновлено N назад» считает бесконечно в сданной сборке
- Подписи полос Ганта (`gxFit`) пересчитываются на каждый `resize` без ограничения частоты
- `dashboard_upgrade.py`: ошибка чтения файла выдаётся как «not valid JSON»; копия в `.autopilot/` не находит шаблон, запускать из каталога навыка
- Запись в `state.js` и `.autopilot/` через Bash хук не ловит (только Write/Edit) — предел назван в `docs/autopilot/claude-code.md`
- `execution sequential-host` стирает запись подписи, но оставляет `gateMark`; запись подписи не атомарна
- Не проверено в браузере: Chrome, Firefox, Safari (только Edge); `file://`; контраст 4.5:1
- Журнал, остатки R22d: старая битая строка попадает в «пропущено» каждого отчёта; журнал из одних битых строк назван «пустым»; последний прогон выбирается до проверки целостности записи; роль в `--share` берётся из журнала как есть (`run_log.py`)
- Роль в журнале не проверена через живой хук `SubagentStop`, только на готовых строках
