# Спецификация: волна 1 правок Autopilot (R01–R06)

## Задача
Убрать три дефекта процесса, стоившие времени в прошлой сборке (потеря статусов тасков из-за окончаний строк, чужой индекс git, пути машины в файлах прогона), и подогнать правила под текущий Claude Code (советник, возобновление после лимита, проверка версии). Шлюзы G1–G4 и независимая приёмка не ослабляются. Волны 2–3 и R19–R21 вне рамок.

## Решение
Объём ~1,2–1,8 тыс. строк с тестами, одна область `skills/autopilot/` + `tests/` + `docs/` + `CHANGELOG.md` → **T0, один таск**.

## Решения по реализации
- **Нормализация** — `state_io.ticket_fingerprint(raw: bytes) -> str` (sha256 нормализованного текста, utf-8) и `state_io.fingerprint_matches(stored, raw) -> bool`: совпало с новым или с любым старым вариантом. Старые варианты: sha256 сырых байтов файла и sha256 текста, у которого окончания строк и BOM перекодированы в четырёх сочетаниях (LF/CRLF × BOM есть/нет) — это закрывает случай «опубликован с CRLF, потом файл стал LF». Правка хвостовых пробелов у уже опубликованного файла старый отпечаток не восстановит — она считается правкой (безопасный отказ, а не тихий сброс). Почему `state_io.py`: его уже копируют все инструменты, включая `codex_dispatch.py`.
- **Кто сравнивает**: `publish_tickets`, проверка в `plan-models`, `codex_dispatch.py:131` — все через `fingerprint_matches`; новый отпечаток пишется в `state.js` при любой публикации.
- **R01b**: сданный таск (`status == "done"`) с изменившимся смыслом → `die(...)` с текстом и командой; `ticket NN accept-edit --note "..."` (только для `done`, `--note` обязателен) запоминает `acceptedFingerprint` = нормализованный отпечаток текущего файла; следующий `tickets` его принимает, переписывает отпечаток и убирает признак. Для не сданных тасков поведение прежнее (сброс). Проверка существующего worktree остаётся как есть.
- **R02a**: в `claude_agent_guard.decision` ветка для `tool_name == "Bash"` — только когда вызов идёт от субагента (`agent_type`/`agent_id` в полезной нагрузке) и идёт незавершённый строгий прогон; разбор команды с учётом `git -C <путь>`, `;`, `&&`, `|`. `install_hook` ставит ещё один PreToolUse с матчером `Bash`; повторная установка идемпотентна, прежние хуки сохраняются. Предел (команда, спрятанная в скрипт или `eval`, не ловится) называется в `docs/autopilot/claude-code.md`.
- **R03a**: функция `machine_path_hits(text)` в `ap.py` с теми же регулярными выражениями, что в `tests/test_no_machine_data.py` (не расширять сверх них); проверка в начале `publish_tickets` по каждому `tickets/*.md` и по `spec.md` прогона, до любой записи состояния.
- **R06**: `parse_claude_version`, константы минимума (2.1.295) и порога предупреждения (2.1.311); подкоманда `claude-version` не требует `state.js`.
- Тесты на документы — проверка подстрок ключевых правил, не всего текста.
