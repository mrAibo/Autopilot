## Что должно заработать

Сданные таски переживают смену окончаний строк, а настоящая правка сданного таска останавливает публикацию с понятной командой; исполнители не трогают чужой индекс, и хук строгого прогона отклоняет `git stash` и `git reset` в их Bash-вызовах; пути машины не попадают в файлы прогона и ловятся при публикации тасков; правила про советник, возобновление после лимита и версию Claude Code описаны в фазах и документах, версия разбирается командой `ap.py claude-version`. Всё покрыто тестами и записано в `CHANGELOG.md`.

Читать сначала: `interfaces.md` (границы и правила), `spec.md` (истории 1–14), `notes.md` (где что лежит) — в папке прогона.

## Из брифа, дословно

> «Отпечаток считается по нормализованному тексту: LF, без хвостовых пробелов, без BOM.»
> «Совпадение с любым из двух (старый или новый) = таск не менялся, отпечаток молча переписывается на новый.»
> «Смена смысла у сданного таска не сбрасывает его молча: останов с сообщением и командой `ticket NN accept-edit --note "..."`.»
> «запрещены `git stash`, `git reset`, `git checkout -- <чужие пути>`; коммит только `git commit --only <файлы зоны>`; перед коммитом `git diff --cached --stat`.»
> «`claude_agent_guard.py` отклоняет `git stash` в Bash-вызовах субагентов строгого прогона»
> «образцы — через `<scratchpad>` и `<repo>`.»
> «абсолютный путь пользователя (шаблоны из `tests/test_no_machine_data.py`) = отказ с указанием файла и строки.»
> «советник — серверный инструмент, субагенты наследуют настройку `advisorModel`, `is_allowed_subagent_model` его не видит.»
> «в строгом прогоне предупредить, если `advisorModel` настроен; предложить `CLAUDE_CODE_DISABLE_ADVISOR_TOOL=1` на время сборки.»
> «исполнитель упал на лимите → `git status` и `git diff` его зоны → `SendMessage` тому же агенту «продолжи», нового не заводить; пункт про незакоммиченные правки зоны.»
> «в сообщение пользователю — время сброса лимита (5-часовое окно и недельное у плана); для Ultra 5-часового лимита нет.»
> «`claude --version` до `init`, разбор строки версии, тест на разбор.»
> «Жёсткий минимум остаётся 2.1.295 … Версии ниже 2.1.311 — предупреждение с перечнем известных проблем, но не отказ»
> «каждое изменение сопровождается тестом и записью в `CHANGELOG.md`»

## Критерии приёмки

- [ ] Файл таска с CRLF и тот же файл с LF дают один отпечаток; `ap.py tickets` не меняет статус сданного таска при смене окончаний строк, BOM или пробелов в конце строк (тест)
- [ ] Таск, опубликованный старым кодом (отпечаток по сырым байтам), остаётся `done`, а в `state.js` оказывается новый отпечаток; случай «опубликован с CRLF, файл стал LF» тоже принят (тест)
- [ ] Правка смысла сданного таска: `ap.py tickets` завершается ошибкой с текстом, содержащим `ticket NN accept-edit --note`; статус и коммит сохранены; после `ticket NN accept-edit --note "…"` публикация проходит; `accept-edit` без `--note` и для не сданного таска отказывает (тест)
- [ ] `plan-models` и `codex_dispatch.py` принимают таск с совпавшим новым или старым отпечатком (тест)
- [ ] `prompts/executor.md` и тело профиля исполнителя из `agent_profiles.py` содержат запрет `git stash`, `git reset`, `git checkout -- <чужие пути>`, правило `git commit --only <файлы зоны>` и `git diff --cached --stat` перед коммитом (тест)
- [ ] `claude_agent_guard.bash_decision` и `decision` отклоняют `git stash`, `git stash pop`, `git reset --hard` в Bash-вызове субагента строгого прогона, пропускают `git commit --only a b`, не вмешиваются в основной сеанс и в не строгий прогон; `install_hook` добавляет хук с матчером `Bash`, повторный вызов ничего не дублирует и не теряет чужие хуки (тесты)
- [ ] `ap.py tickets` с `C:\Users\<имя>\…` или `/home/<имя>/…` в файле таска или в `spec.md` прогона отказывает сообщением с файлом и номером строки, не меняя `state.js`; `<repo>` и `<scratchpad>` проходят (тест)
- [ ] В `phases/4-plan.md` и в промптах нет путей машины, образцы идут через `<scratchpad>` и `<repo>`; `tests/test_no_machine_data.py` зелёный
