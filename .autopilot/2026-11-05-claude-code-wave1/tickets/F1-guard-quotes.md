# F1 — Хук git: разделители только вне кавычек

**Требования:** R02a
**Зависит от:** —
**Зона:** `skills/autopilot/tools/claude_agent_guard.py` · `tests/test_wave1.py`
**Волна:** 2
**Ревью:** да — ремонт ветки
**Модель:** сильная

## Что должно заработать

`bash_decision` в `claude_agent_guard.py` не отклоняет коммит, у которого в сообщении встречаются `;`, `&`, `|` или перевод строки внутри кавычек.

Читать сначала: `interfaces.md`, `spec.md` (история 5) в папке прогона.

## Находка ревью, дословно

> «Команда режется по `;`, `&`, `|` и переводам строк внутри кавычек, поэтому текст в сообщении коммита даёт ложный отказ. Проверено: `git commit -m "a; git reset notes"` и `git commit -m "x\nrun git stash later"` возвращают отказ. Условие: разделители считаются только вне кавычек, а `git commit -m "…; git stash …"` и многострочное сообщение проходят.»

## Критерии приёмки

- [ ] `git commit -m "a; git reset notes"` и коммит с многострочным сообщением, где есть слова `git stash`, проходят (тест в `tests/test_wave1.py::BashGuard.test_bash_decision`)
- [ ] `git stash`, `git stash pop`, `git reset --hard`, в том числе после `&&`, `;` или `|` вне кавычек, по-прежнему отклоняются (существующие тесты зелёные)
- [ ] Полный прогон `python3 -m unittest discover -s tests` зелёный
