## Что должно заработать

Обычный прогон получает четыре постоянных лёгких профиля при `init`; `ap.py` подсказывает строкой `↑`, когда контекст главной сессии вырос; `tools/measure-run.py` показывает стартовый контекст, тип агента и ходы оркестратора между субагентами; у fix-тасков обычного прогона записан маршрут, а отчёт по моделям не теряет строки.

> «Строгий прогон не меняется: свои профили на таск, guard, подписи, аттестация.»

> «Это подсказка, не вопрос и не останов; … Журнал не найден — строки нет.»
> «`tools/measure-run.py` считает шаги главной сессии между возвратом субагента и следующим запуском субагента и токены на эти шаги. Читаются числа, имена инструментов и тип агента; текст не читается и не сохраняется.»

> «в `report-run` на журнале с записями субагентов нет строки «не указана» там, где модель есть в журнале субагента; тест на это.»

## Критерии приёмки

- [ ] `init` обычного прогона создаёт в `.claude/agents/` четыре файла с именами из брифа и названными инструментами; в frontmatter нет `model` и `effort`; в тексте нет пути таска и имени прогона
- [ ] Повторный `init` (новый прогон после сданного) не переписывает неизменённые профили; профиль с изменённым текстом возвращается к эталону; файлы прошлых прогонов и чужие файлы рядом целы
- [ ] `init --strict-routing` четыре постоянных профиля не создаёт; сбой записи профиля даёт строку `!`, а не падение `init`
- [ ] `run_log.role_of("autopilot-executor")` даёт `executor` (так же три другие роли), прежние имена с номером таска разбираются как раньше
- [ ] Пока нет ответа про уровень пользователя, `init` печатает одну строку `?`; `agents install-user` без `--by-user` отказывает и ничего не пишет; с цитатой пишет четыре файла в `agents/` папки настроек Claude Code (тест — через `CLAUDE_CONFIG_DIR`); `--decline` запоминает отказ; после ответа строки `?` нет
- [ ] В текстах фаз назван профиль для каждой роли (исполнитель, точечное ревью, ревью ветки, проверка покрытия G2, слепая приёмка, разведка, память, ADR) и запасной путь «Agent type not found → `general-purpose`, одна строка пользователю, никогда не останов»; рядом сказано, что модель и усилие передаются параметром вызова всегда; `5-host-claude.md` называет их для обычного прогона, строгий текст не изменён
- [ ] При контексте главной сессии выше порога `stage build`, `stage review`, `stage final` и `init` печатают ровно одну строку `↑` с числом; ниже порога и без журнала строки нет и команда не падает; `AUTOPILOT_CONTEXT_HINT` меняет порог, 0 выключает; усечённое имя папки журнала находится
- [ ] `0-preflight.md` говорит начинать новую сборку в старом чате с этой строки; `0-instruments.md` и `0-modes.md` описывают `↑` как подсказку, которых может быть две
- [ ] `tools/measure-run.py` на фикстурной папке журналов печатает по каждому контексту стартовый контекст и тип агента, и таблицу «ходы оркестратора между субагентами» (шаги и токены на посадку); `.meta.json` с BOM читается
- [ ] В `docs/autopilot/measuring-cost.md` — замер по настоящим журналам этого проекта: стартовый контекст по типам агентов («до» лёгких профилей) и среднее число шагов оркестратора на таск, с оговорками; рядом одна строка-заготовка «Решение по R05: …» с фактическим средним (решение впишет оркестратор)
- [ ] `ticket F1 route --model … --effort … --reason …` в обычном прогоне записывает `routing` без создания профиля; недопустимая модель (Fable, Opus без подтверждения) отказывает; строгая ветка не изменена
- [ ] `report-run` на журнале, где у субагентов (включая F-таск) модель есть, не печатает «не указана»
- [ ] `collapse_agents`: строка хука есть только для одного `agent_type` — журнальные строки других `autopilot-…` агентов остаются в сумме
- [ ] Ничего из раздела 4 брифа не сделано; guard, подписи, правила Opus и Fable не тронуты
