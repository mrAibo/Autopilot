# Спецификация: закрыть известные баги из PROGRESS.md

## Задача
В `.autopilot/PROGRESS.md` («Известные баги») остались четыре группы дефектов (перечень в брифе): `plan-fact` не сверяет строку в доказательстве и стирает ручные «план: …»; `land_check` не узнаёт свой коммит без префикса темы и не видит правки через merge-коммиты; ошибочный `confirmed` у `blocker confirm` не исправить; `redproof` принимает ImportError. Закрыть, не трогая остального.

## Истории

| # | Метка | История | Приёмка |
|---|-------|---------|---------|
| 1 | R01 | «сделано» в `plan-fact record` принимается, когда доказательство — `путь:N`, где `путь` под корнем проекта, а `N` от 1 до числа строк файла, либо `путь::имя`, где `имя` встречается в файле. Хоть одно такое — довольно; иначе пункт «не сделано», как и сейчас (понижение с пояснением) | `a.py:9999` при файле из 3 строк и `a.py::нет_такого` → «не сделано»; `a.py:2` и `a.py::имя` из файла → «сделано» |
| 2 | R02 | `record` пересобирает `concerns` «план: …», удаляя только строки, которые сам записал раньше (точное совпадение с `план: <id> — <статус> — <текст>` по прежним `planFact.items` не-«сделано»); любая другая строка с префиксом «план: » остаётся | ручной `add concerns "план: вручную …"` переживает два `record`; повторный `record` не дублирует свои строки |
| 3 | R03 | `ticket NN land` пишет в коммит трейлер `Autopilot-Ticket: NN`; `land_check` считает коммит таска своим, если тема начинается с id (как сейчас) **или** в трейлерах есть `Autopilot-Ticket` с этим id | коммит с темой без префикса, но с трейлером, не даёт отказа «чужие коммиты»; без трейлера и без префикса — даёт |
| 4 | R04 | Для merge-коммита (≥2 родителей) `land_check` берёт файлы как изменение относительно первого родителя (`diff --name-only <merge>^1 <merge>`), а не пустой `show`; правка, пришедшая в зону через merge чужой ветки, видна как чужая | merge-коммит, внёсший правку вливаемого файла после старта таска, → отказ; merge, свой по трейлеру/теме, → нет |
| 5 | R05 | `blocker confirm --id B01 --verdict not-confirmed --quote "…" --by-user "<слова пользователя>"` исправляет `confirmed` у ещё открытого блокера: вердикт заменяется, блокер `downgraded`, условие уходит в `concerns`, прежний вердикт хранится в `secondPass.replaces`, в журнал — событие `act=corrected` с цитатой пользователя. Без `--by-user` отказ остаётся и подсказывает команду; другие сочетания (повтор `confirmed`, поправка `not-confirmed`) — отказ | тесты: поправка с цитатой работает; без цитаты — отказ; пустая цитата — отказ |
| 6 | R06 | `ticket NN redproof` отказывает («тест не по-настоящему красный»), если в выводе строка с `ImportError`, `ModuleNotFoundError` или `cannot import name`; прочие падения — красные как раньше | тест: код 1 + вывод `ImportError: cannot import name 'f'` → отказ; `AssertionError` → принят |
| 7 | R07 | R28 и R33–R35 не строятся и не меняются | `git diff --stat` не называет их файлы |

## Решения по реализации
- Все правки в `skills/autopilot/tools/{plan_items,land_check,ap}.py`; на каждую — регрессионный тест в `tests/`; запись в `CHANGELOG.md` («Unreleased»); ADR `0028`; из «Известные баги» в `.autopilot/PROGRESS.md` убирают закрытое (делает оркестратор).
- `skills/autopilot/phases/kind-bug.md` и справка `ap.py` — одна строка про ImportError, если там сказано иное.

## Вне рамок
R28, R33–R35; остальные пункты «Известные баги» (`ticket NN review`, `lessons`, `worktrees.link_deps`, `commit_paths`, расход, сервер, `test_gate_sign`) — не в брифе.
