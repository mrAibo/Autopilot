## R14 — `serve()` без PowerShell (T/ap.py 817–1105)
Код: `_run` (817), `_ps` (825: `powershell -NoProfile …`, timeout 10 c), `cmdline(pid)` (829: на Windows `Get-CimInstance Win32_Process`; иначе `ps -p`), `processes()` (835, PowerShell/`ps`), `is_ours` (859), `is_guarded_server(cmd)` (868: наш `ap.py` + `--serve <порт>` в командной строке), `kill`, `recorded()` (882: `serve.pid` = «порт pid»), `http_ok(port)` (890: GET `/dashboard.html` → 200), `serve_token()` (940, файл `.autopilot/serve.token`; нет файла — создаётся), `make_server(directory, port, token)` (972; внутренний `Handler`: `allowed()`, `tokenless_page()`, `do_GET/do_HEAD`, `end_headers`), `run_server(port)` (1061: токен читается ОДИН раз при старте и держится в замыкании), `page_url` (1065), `serve(state, with_token)` (1071), `stop_now` (1105: `is_ours(cmdline(pid))` — но в отдельном процессе через `STOP_DELAY`), `stop_later` (1119).
Горячий путь: `main()` (4015) на каждой команде, кроме `--no-serve`/`finish`/`--stop`, зовёт `serve(state)` (4205) → при живом сервере `http_ok(port) and is_guarded_server(cmdline(pid))` — `cmdline` = PowerShell 0,56 c. Другой PowerShell-путь: `serve()` при `state["finishedAt"]` зовёт `kill_orphans(keep=pid)` → `processes()` → PowerShell на каждую команду после сдачи (в брифе не упомянуто). `ap.py url` (4079) сам печатает `page_url(port)` без проверки живости (и не зовёт `serve`, если порт записан).
Решение «подтверждение по HTTP»: добавить в `Handler` открытый путь (например `/.ap-ping`, не в `OPEN_PAGES`, не требует `?t=`) с ответом `hmac(token, "autopilot-ping|<порт>")` (токен не уходит); в `serve()` клиент считает то же от `serve_token()` и сравнивает `hmac.compare_digest`; совпало — вернуть URL без `cmdline`; не совпало/нет ответа — прежний путь `is_guarded_server(cmdline(pid))`. Проверки Host/Origin/`Sec-Fetch-Site` в `allowed()` остаются (ping идёт на 127.0.0.1:порт с Host=127.0.0.1:порт). Тот же ответ решает R20 «удалённый `serve.token`» (см. R20): токен в файле удалили → `serve_token()` сгенерит новый → ответ не совпал → перезапуск.
Тесты (как подменяется): `tests/test_followups_token.py::AddressPrinting` — `test_serve_reports_the_running_server_without_the_token` (121) и `run_main` (153; используется `test_real_serve_path_of_stage_and_init_prints_no_token`) патчат `recorded`, `http_ok`, `is_guarded_server`, `cmdline` и очищают `CI`/`SSH_CONNECTION`. ВНИМАНИЕ: новая функция «ответ сервера» должна быть так же подменена в этих двух местах, иначе `serve()` не найдёт сервер на порту 8123, дойдёт до `kill_orphans()` (реальные `processes()`/PowerShell) и ПОДНИМЕТ настоящий сервер. Лучше вшить проверку в уже подменяемую `http_ok` либо вынести в одну функцию и добавить в патчи. `tests/test_ap_audit.py::Server` (148–200: реальный `--serve` в процессе, `ask(path, host)`; `test_own_server_is_recognised_by_its_command_line` 197) и `tests/test_followups_token.py::TokenlessPage` (25: `make_server(dir, 0, TOKEN)` в потоке, `fetch`) — готовая основа для теста «здоровый сервер не запускает PowerShell»: подменить `m._ps` и `m._run` (на Linux `cmdline` идёт через `_run`, не `_ps`) на `side_effect=AssertionError`, `recorded` → `(server_port, os.getpid())`, `CI=""`. «Чужой процесс на порту»: поднять `http.server` без ping на свободном порту → `serve()` не возвращает его URL как свой (ожидаем `kill_orphans`/`free_port`/Popen — подменять `subprocess.Popen`).

Токен читается ОДИН раз: `run_server` → `make_server(A, port, serve_token())` — замыкание `token`; если `.autopilot/serve.token` удалить, сервер продолжает отвечать со старым, а `serve_token()` в следующей команде (`page_url`, `ap.py url`) СОЗДАЁТ НОВЫЙ файл → адрес с новым токеном → 403 (известный баг PROGRESS «Сервер: удалённый serve.token даёт 403 до перезапуска»). Где `ap.py` проверяет токен при следующей команде: в `serve()` (1071) — сейчас не проверяет вовсе (`http_ok` + `is_guarded_server`); `serve_token()` вызывается только из `page_url`, `run_server`. Решение: тот же ping, что в R14 (hmac от текущего `serve_token()`): не сошёлся → `kill_orphans()`/перезапуск сервера (он перечитает файл). Для `ap.py url` (4079): если порт записан, не вызывается `serve` → тоже проверить.
Тесты: сервер — `tests/test_followups_token.py::TokenlessPage` (make_server в потоке) + `AddressPrinting`; `tests/test_ap_audit.py::Server` (148–200). Новый тест для удалённого токена: поднять `make_server` с токеном из файла, удалить файл, вызвать функцию подтверждения → «не наш» → `serve()` пытается перезапустить (патч `subprocess.Popen`, `free_port`). Страница — node-vm: `tests/test_dashboard_views.py` `HARNESS` (контекст `{document, localStorage, navigator, location:{protocol:'file:', search}}`, `document.createElement: () => ({remove(){}})`, `document.head.appendChild`) — для R20 нужен вариант `protocol:'http:'`, `search:'?t=bad'` и вызов `onerror` у созданного скрипта (в харнессе `createElement` возвращает пустой объект — расширить, чтобы можно было вызвать `s.onerror()` дважды и проверить, что новый таймер не заведён: нужны `setTimeout` стабы). Вторая основа: `tools/check-dashboard-browser.py` (Linux CI, реальный браузер — не трогать), `tests/test_followups_dashboard.py` (node-vm рядом).
