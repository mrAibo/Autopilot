## Что должно заработать

Все тесты репозитория можно прогнать одной командой параллельно с общим итогом в обычном формате; обычная команда `unittest discover` и CI не тронуты.

## Из брифа, дословно

> **R17. Тесты самого Autopilot идут параллельно**
> - Замер 2026-11-16, Windows, Python 3.14, один процесс: 959 тестов за 532 с, все зелёные, 5 пропущено. Тридцать самых медленных вместе дают около 150 с (самый долгий 17 с); остальное — длинный хвост тестов по 3 с в `test_ap.Run`, каждый из которых несколько раз запускает `ap.py` отдельным процессом. Делить есть что: одного медленного теста, который задаёт нижнюю границу, нет.
> - Сначала выяснить, сколько из этих 3 с уходит на проверку сервера и PowerShell (R14) и не хватает ли тестам `--no-serve`: если дело в этом, часть выигрыша приходит без параллельности. Результат — одна строка в отчёте.
> - `tools/` получает запускатель на стандартной библиотеке, который делит файлы тестов между процессами и печатает общий итог в том же формате (всего, упало, пропущено). Обычная команда `python3 -m unittest discover -s tests` остаётся рабочей и остаётся командой CI, пока параллельный прогон не показал те же числа три раза подряд.
> - Тесты, которым нужен общий ресурс (порт, домашняя папка), помечены и идут последовательно.
> - В `AGENTS.md` записано фактическое время до и после.

Полный текст — раздел R17 и разделы 1, 4, 5 брифа (`2026-11-17-brief.md` в папке сборки); к сборке относятся только волны 4–6.

## Критерии приёмки

- [ ] `python tools/run-tests.py` делит тесты между процессами (по умолчанию число ядер, `-j N`), тяжёлый файл `test_ap.py` делится по классам; печатает `Ran N tests in X.XXXs` и `OK (skipped=S)` либо `FAILED (failures=F, errors=E, skipped=S)`; код выхода 1 при падении; вывод упавших тестов показан
- [ ] Тесты, которым нужен общий ресурс (порт, домашняя папка, `AUTOPILOT_HOME`), помечены атрибутом класса `serial = True` и идут последовательно после параллельных; найти такие — по коду, а не по догадке (`notes.md` R17 — кандидаты); тест, что помеченный класс попал в последовательную группу
- [ ] `--list` печатает разбиение на группы без запуска; тест `tests/test_run_tests.py`: дробление на группы и сложение итогов (без запуска всего набора)
- [ ] Запускатель компилируется (`python -m compileall -q tools`); ни `.github/workflows`, ни команда CI не менялись
- [ ] Замер: полный параллельный прогон на этой машине — три прогона подряд дают те же числа (всего, упало, пропущено), что `python -m unittest discover -s tests`; время «до» (последовательный) и «после» записано в `AGENTS.md` в «Подводные камни» строкой с датой и числом процессов (полный прогон ≈ 9 мин: гоняй в фоне)
- [ ] В отчёте одна строка: PowerShell и сервер входят ли в 3 с теста (по `notes.md` R17 — нет, тесты уже на `--no-serve`; сверь замером одного теста)
