# Спецификация: доделки после аудита

## Задача
Пользователь доделывает прошлую сборку. Токен дашборда обходится: страница с данными отдаётся без токена, а адрес с токеном печатается при каждой команде и попадает в чат. Ключ подписи создаётся с окном гонки. В тексте правил два места читаются как противоречие. Дашборд велик на первом экране: «Сейчас» занимает весь экран заголовком, «Требования» держит все 29 карточек в одной колонке. Все таски ушли на sonnet/high, потому что маршрут выбирают регулярные выражения по словам в тексте таска, а он хочет «выбирать модели более интеллигентно».

## Решение
- Страница по адресу без токена показывает только оболочку без данных и понятную подсказку; данные и снимок — только с токеном.
- Адрес с токеном печатается только по явной команде `ap.py url` (и голым `ap.py`, которым пользователь сам поднимает дашборд); в строке состояния и в `init` — адрес без токена.
- Ключ `gate.key` создаётся целиком или не создаётся: никто не видит пустой файл и не удаляет чужой ключ.
- Текст правил говорит то, что делает код: `finish --by-user` пропускает отказы, но строки манифеста не меняет; тест это закрепляет.
- «Сейчас» открывается компактно: заголовок одной строкой, ниже сразу таски и требования; колонка «Принято» свёрнута до нескольких карточек и кнопки «Показать все N».
- Маршрут таска определяет планировщик: класс, риск и причина записаны в таске; роутер читает их и зону, а не слова. Регулярные выражения по тексту удалены.
- Копия страницы `.autopilot/dashboard.html` обновляется из шаблона на `init`, `stage` и `finish` (A01).

## Решения по реализации
- **Токен-страница (R01):** обработчик для `OPEN_PAGES` без верного токена читает файл и подменяет снимок между маркерами на `window.STATE=null;`; с верным токеном отдаёт файл как есть. Файл на диске не меняется (`file://` и `write_snapshot` как раньше). Причина: сервер статический, переписывать файл под каждый запрос нельзя.
- **Адрес без токена (R02):** `page_url(port, with_token)`; `serve()` и `init` печатают `http://localhost:P/dashboard.html`; новая команда `url`; голый `ap.py` печатает адрес с токеном, потому что его вызывает сам пользователь. Токен в чат не выводится ни одной автоматической командой.
- **Атомарный ключ (R03):** ключ пишется во временный файл рядом (`<path>.<pid>.tmp`, `0o600`), затем `os.link(tmp, path)` (падает, если файл есть) и удаление временного; проигравший читает победителя. Пустой старый файл заменяется через `replace_with_retry`. Причина: `link` атомарен, пустого окна нет. Запасной путь для томов без `link`: `O_EXCL`-создание с полной записью (`shortcut: …`, в комментарии кода).
- **Текст правил (R04):** правим действующие тексты (`phases/1-manifest.md`, `phases/8-final.md`, `AGENTS.md`), код не меняем: он уже не трогает строки. Формулировка R24 в спеке сборки 2026-11-08 — история, её не правим; в сданных сборках она остаётся как была.
- **«Плотнее» (R05.1):** означает свёртку «Принято»; остальные колонки и полосы не меняются, потому что в них мало карточек.
- **Компактность (R05):** только шаблон и стили; новые строки в оба словаря `L`; состояние свёртки `UI.rbOkAll` (в память страницы, как `UI.rb`); приём свёртки `rowsList`.
- **Оценка планировщика (R07):** `assess_ticket` читает зону, `**Объём:**`, `**Класс:**`, `**Риск:**`; `hard`/`vague` по словам удаляются (класс «сложный» даёт `algorithm`; неясность планировщик пишет в причину). `**Причина класса:**` разбирается и пишется в `routing.reason`; пустая или длиннее 200 символов — отказ `check-plan`. `agent_profiles.py` берёт оценку из той же функции.
- **Обновление страницы (A01):** `refresh_dashboard` сравнивает копию с шаблоном (по отпечатку шаблона без снимка) и зовёт `dashboard_upgrade.upgrade`.
