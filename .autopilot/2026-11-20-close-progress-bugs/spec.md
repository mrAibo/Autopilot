# Спецификация: закрыть баги и хвосты из PROGRESS.md

## Задача
Прошлая сборка оставила в `.autopilot/PROGRESS.md` известные баги в `plan-fact record`, `land_check`, `blocker confirm`/`redproof`, вердикты второго прохода нигде не хранятся, а CI всё ещё гоняет последовательный `unittest discover`. Нужно это закрыть, не трогая R28 и R33–R35.

## Решение
Каждый баг получает правку и регрессионный тест; вердикт второго прохода сохраняется в самом блокере (сейчас журнал его не хранит; старые блокеры без `secondPass` читаются как раньше); CI запускает `tools/run-tests.py`.

## Решения по реализации
- `record` по частям: прежние вердикты берутся из `state["planFact"]["items"]` (id, статус, доказательство), новые накладываются по id — потому что бриф называет заменой целиком багом. Старая фраза в `AGENTS.md` «заменяет все вердикты целиком» уточняется.
- Доказательство «сделано» проверяет `ap.py` (знает ROOT), а `build_plan_fact` получает необязательный `root` — чистая функция остаётся чистой без `root`.
- «Сам таск» узнаём по теме коммита, а не по автору: исполнители обычно не коммитят, а `land` ставит тему `T%s: …`.
- Проект в подпапке: префикс из `git rev-parse --show-prefix` приписывается к путям зон перед сравнением с `git diff --name-only`.
- `secondPass` — новое необязательное поле блокера; `blocker_ledger` его не требует (старые журналы читаются).
- Отвергнуто: считать «не красный» по тексту любой ошибки импорта — красный тест на ещё не написанную функцию законно падает с `ImportError`; режем только синтаксис, «команда не найдена», 126/127, ноль тестов (граница известна, записывается в код комментарием `shortcut:`).
