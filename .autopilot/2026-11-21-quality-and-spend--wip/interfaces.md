## Правила проекта (из «Договорились»)
- Не менять шлюзы, слепоту приёмки (`ap.py blind`), подписи, guard, правила Opus и Fable. Opus выключен, Fable не допускается; `dropped` ставит только пользователь; `main` в `origin` — только по слову.
- Исполнитель не коммитит (коммитит оркестратор через `ticket NN land`). `.claude/settings.json`, `ROADMAP-claude-code-2026-11.md`, `BRIEF-2026-11-orchestrator-spend.md` в корне не коммитить.
- Тесты, копирующие `ap.py` в харнесс, копируют каждый импортируемый модуль (`state_io.py`, `process_containment.py`, `run_log.py`, `doc_check.py`, ...).
- Каждый баг — регресс-тест; `CHANGELOG.md` («Unreleased»), `AGENTS.md`, ADR `0035` ведёт **только таск 05**; остальные в них ничего не правят.
- `ap.py` правят таски 01, 02, 04 строго подряд (зависимости); не параллелить. Страница дашборда: потолок шаблона 450 КБ.
- Каталог проекта в тестах и подпроцессах — временный; тест не читает реальный `~/.claude`.

## Границы, решённые в спецификации

**`ap.py` (T01) — упавшие тесты на `land`.** Новая функция `failed_tests(out) -> list[str]`: строки вида `FAIL: имя (модуль.Класс)` и `ERROR: имя (модуль.Класс)` из вывода unittest (также `FAIL: имя (…)` после `=====`), без повторов, порядок сохраняется. Красный `land` печатает: `land NN: стоп на шаге «проверка» — красная: код C, упало F`, затем блок `упавшие тесты (до 20):` и по строке `  - FAIL: …`, затем `хвост вывода (последние 15 строк):` и сами строки с отступом. Код выхода по-прежнему 2, коммита нет, `tk["lastCheck"]` как раньше. Нет FAIL/ERROR-строк (вывод не unittest) — блок имён пропускается, остаётся хвост.

**`ap.py` (T02) — целевая проверка.** Строка таска (файл `tickets/NN-*.md`, через `ticket_files`): `Целевая проверка: \`<команда>\`` (допустимы префиксы `*`, `-`, `>` и `**…**` вокруг названия). Функция `targeted_check_command(state, ticket_id) -> str|None`. `land`: если строка есть — гонит её вместо полной (те же правила: код 0, ≥1 тест, 0 упавших; тот же вывод красного из T01); в `state["targetedLands"]` (список id) попадает id; нет строки — прежнее поведение. `stage review` (если `targetedLands` непуст): запускает полную проверку (`full_check_command`), красная → отказ в переходе со списком упавших (тот же формат), зелёная → `state["tests"]` = итог, `targetedLands` очищается. `finish`: если `targetedLands` непуст (посадки после ревью) — то же, красная — отказ. Нет строки «Полная проверка» — `stage review` и `finish` ничего не запускают, строка-предупреждение.

**`doc_check.py` (T04), новый модуль** `skills/autopilot/tools/doc_check.py`: `claimed(text) -> set[str]` — имена из backticks вида `ap.py <cmd>` (команда: `[a-z][a-z0-9-]*`) и `--flag` (`--[a-z][a-z0-9-]+`); `known(ap_source) -> (cmds, flags)` — команды из `cmd == "…"`/`cmd in (…)` и флаги из `opt.get("…")`, `opt["…"]`, `"--…"` и докстринга `ap.py`; `check(root, ap_path, files) -> list[str]` — строки расхождений `файл: ap.py <cmd> — такой команды нет` / `--flag — такого флага нет`. Файлы: `CHANGELOG.md` раздел «Unreleased» + `docs/adr/*.md`, изменённые коммитами прогона (`git log --name-only` от `baseCommit`; нет baseCommit — все ADR и Unreleased). `ap.py doc-check`: печатает расхождения (по строке), код 1 если есть, 0 нет. `finish` вызывает `doc_check.check` в try/except и добавляет в `notes` строку `! doc-check: N расхождений (ap.py doc-check)` — не блокирует.

**Фазы (T03):** текст, тесты `tests/test_text_split.py` (размер обычного пути) должны проходить.

**Дашборд-проверка (T06):** в `tools/check-dashboard-browser.py` — функция проверки, что в каждом из шести дизайнов, на ширинах 1440 и 400, при фикстуре с `planFact {done, total}` DOM содержит `section.card.w h3.wt` с текстом `план: N из M`; проверка пропускается без Chrome (как остальное).
