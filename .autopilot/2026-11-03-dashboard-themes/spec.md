# Спецификация: темы дашборда

## Задача
Дашборд по умолчанию недостаточно информативен, а вид у него один. Нужно, чтобы вид можно было выбирать, и чтобы видов было несколько, более информативных (образец — Figma «новые виды»: Обзор · Таймлайн · Требования · Ресурсы · Итог). В дашборде должен быть логотип проекта.

## Решение
В шапке дашборда, рядом с языком и светлой/тёмной темой, появляется выбор темы (вида). Выбор запоминается в браузере. Одно состояние `state.js`, один файл-шаблон: тема меняет только то, какие из уже посчитанных блоков показаны и в каком порядке. Ни `ap.py`, ни формат `state.js` не меняются.

Темы (id → название ru/en):
| id | Название | Что показывает |
|----|----------|----------------|
| `overview` | Обзор (по умолчанию) | шапка состояния, строка KPI (токены, работают сейчас, рабочие копии, повторы и починки), трек этапов, активные и готовые таски, шлюзы G1–G4, сводка требований, последние события |
| `timeline` | Таймлайн | трек этапов, таски по волнам с длительностью, лента событий целиком |
| `requirements` | Требования | все требования со статусами и фильтрами, шлюзы, покрытие, остатки (заглушки, допущения) |
| `resources` | Ресурсы | KPI токенов, таблица маршрутов моделей по таскам, рабочие копии и изоляция |
| `summary` | Итог | результат сборки, тесты, слепая приёмка, отчёт, допущения, замечания; до финала показывает, чего ещё нет |
| `classic` | Классика | нынешний вид без изменений |

## Оценка сложности и способ (R04)
Сложность невысокая — один таск-цепочка размера T1: `render()` уже считает все данные один раз, новым является только раскладка блоков и один вид (таймлайн по таскам). Способы:
| Способ | Вердикт |
|---|---|
| **Реестр тем в одном шаблоне** (`VIEWS`), блоки из `render()` переиспользуются | выбран: меньше всего кода, одно место правки, `ap.py`/`state.js` не трогаются |
| Отдельный HTML-шаблон на каждую тему | отвергнут: шесть копий 1700 строк, расходятся с `dashboard_upgrade.py` и тестами |
| Только CSS-переключение (`display:none` по теме) | отвергнут: нельзя менять порядок и состав блоков, всё равно строится лишнее |
| Внешние тематические пакеты (подгрузка файла темы) | отвергнут: дашборд открывается и с `file://`, подгрузка файлов там ломается |
Состав шести тем взят из видов Figma (Обзор · Таймлайн · Требования · Ресурсы · Итог) плюс «Классика»; число «несколько» в брифе не названо, шесть — решение сборки. Состав и название каждой темы правятся одной строкой таблицы `VIEWS`.

Уточнение происхождения: «Классика», запоминание выбора, перенос переключателя в узкой панели, фокус, обрезание списков, чтение `state.js` без префикса, документация и запись в `CHANGELOG.md` — не новые возможности, а проработка R01–R10i и G01–G02 (родитель указан в таблице историй); тест через `node` — способ проверки, он пропускается, если `node` нет.

Глубина «обычная»: пустое состояние, ошибка и обрезание списков продуманы там, где без них вид ломается:
- **Пусто**: нет тасков / требований / лент / токенов — блок показывает короткую подпись «ещё нет» вместо пустоты или исключения.
- **Рост**: списки требований и ленты обрезаются и раскрываются «показать ещё» (механизм `data-more` уже есть).
- **Неизвестная тема в `localStorage`** → `overview`.
- **Фокус**: после перерисовки фокус остаётся на кнопке темы (`data-view` в `focusAttrs`).
- **Узкая панель** (рядом с чатом): переключатель тем переносится в строку/прокручивается, не ломая шапку.

## Решения по реализации
- **Один шаблон, реестр тем.** Блоки `render()` остаются строками-переменными; добавляется таблица `VIEWS = {id: {order, build(ctx)}}`, где `ctx` — уже посчитанные блоки. Так новые темы — новые строки таблицы, а не копии шаблона. Почему: данные уже посчитаны один раз; отдельные шаблоны разошлись бы с `dashboard_upgrade.py` и тестами.
- **Переключение без перезагрузки**: клик по `data-view` → `localStorage` + `render(CUR.lang)` (как язык). Таймер `tick` обновляет только таймеры и работает во всех темах, потому что использует общие `data-since`.
- **Лого**: знак — инлайн `<svg>` (символ в начале страницы и `<use>`), класс `brandmark`; слово `autopilot` — HTML-текст. Класс `logo`, `const LOGO =` и ссылки на PNG не возвращаются (их запрещает `tests/test_brand_assets.py`).
- **Тесты**: Python-тесты по строкам шаблона (реестр тем, ключ хранилища, `data-view` в `focusAttrs`, символ лого, id всех шести тем и ключи i18n в обеих локалях) и один тест, который запускает `node` на извлечённом из шаблона JS с фикстурой `STATE` — если `node` не найден, тест пропускается. Приёмка в браузере — на живом дашборде.
- Два файла правит первый тикет и далее всё идёт в один и тот же `dashboard-template.html`, поэтому тикеты шаблона идут последовательно; правка `dashboard_upgrade.py` независима.
