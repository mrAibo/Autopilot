**Требования:** R17, R18, R19, R21, G01, R23, R24, R25, R26, R27, R29, R30
**Зависит от:** 01, 02

**Ревью:** да — риск: подпись подтверждения и цитата пользователя

## Что должно заработать

`ap.py` получает команды `opus propose|approve|status`, хранит подписанное подтверждение пользователя и использует его в `plan-models --apply`: подтверждённые таски идут на Opus, для ремонта и ревью ветки заводятся закреплённые профили `-opus`. Спецификация: §4.7 (`ap.py opus`, `plan-models`).

## Критерии приёмки

- [ ] `ap.py opus propose` перечисляет pending-таски с пометкой `**Модель:** opus` и таски, для которых `premium_candidate` истинна; для каждого печатает id, название, причину и строку «дороже Sonnet-таска, не измерено»; ничего не пишет в state (тест)
- [ ] `ap.py opus approve --tickets 02 --by-user "<цитата>"` пишет `opusApproval.tickets == ["02"]`, добавляет `{at, quote}` в `quotes`, ставит `sig`; отказывает без `--by-user`, без `--tickets` и `--roles`, с неизвестным id таска и с ролью вне `repair|reviewer` (по тесту на условие)
- [ ] в strict-прогоне `approve` без возможности подписать (нет ключа) отказывает; в прогоне без ключа `sig` равна `null`; повторный `approve` расширяет множества и не стирает прежние цитаты
- [ ] цитата проходит редактор секретов проекта: ключ в `--by-user` не попадает в `state.js`, журнал и вывод (тест с токеном формы `sk-…`)
- [ ] `ap.py opus status` печатает таски, роли и цитаты текущего подтверждения; пусто — «Opus не включён»
- [ ] `plan-models --apply` с `opusApproval.tickets` маршрутизирует эти таски на opus-профиль, остальные как раньше; без `opusApproval` результат побайтно совпадает с прежним (тест на оба случая)
- [ ] при непустом `opusApproval` `plan-models --apply` дополнительно заводит закреплённые профили `autopilot-reviewer-opus-<run>` и `autopilot-executor-repair-opus-<run>` и пишет `opusAgents`; без подтверждения их нет и `opusAgents` не записывается
- [ ] пометка `Модель: opus` без `opusApproval` не меняет маршрут (тест)
- [ ] `ap.py` не вводит способа снять строку манифеста (`dropped`) через `--by-user` или `opus` (тест: команды не меняют манифест)
- [ ] все ранее существующие тесты проходят; добавленные лежат рядом с кодом
