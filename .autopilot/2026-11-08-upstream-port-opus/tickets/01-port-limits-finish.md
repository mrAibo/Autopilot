## Что должно заработать

`ap.py` перестаёт позволять прогону ходить кругами и называть себя «сданным», когда это не так: упавший таск снова идёт только по словам пользователя, слепая приёмка бывает дважды, G1 всегда равен манифесту, `finish` либо отказывает со списком, либо сдаёт «с оговорками» по `--by-user`, а доступность записи в git проверяется до брифинга. Спецификация: §4.0–4.6.

## Из брифа, дословно

> «Портировать нужно не копированием: наш `ap.py` разошёлся с апстримом (подписанные гейты, блокеры, маршрутизация). Каждый фикс переписывается под наш код с одним регрессионным тестом (как в порте 2.2.1, коммиты `a436a78`).» — R01
> «A1. `ap.py` отказывает в третьем `ticket NN repair` и третьем `ticket NN retry` (лимит 2 на каждый). Отказ даёт команду, а не только текст фазы.» — R02
> «A2. Упавший таск (`failed`) снова идёт в работу только через `ticket NN reset --by-user "<цитата пользователя>"`. Цитата пишется в таск (`reopenedByUser`) и в журнал, счётчики `repairs` и `retries` обнуляются. `reset` без `--by-user` на упавшем таске отказывает.» — R03
> «A3. Слепая приёмка: не больше двух кругов за прогон (проверка, таск `F2`, одна перепроверка). Счётчик `blindRounds`, сбрасывается в `reopen`. Третий `blind` отказывает с подсказкой `add report` для остатка.» — R04
> «A5. В `phases/5-repair.md`: сбой окружения (таймаут, не грузится нативный модуль, порт, неработающий сервис, путь только на этой машине) это `fail` с вопросом пользователю, а не ремонт.» — R06
> «B1. G1 идёт за манифестом: вычисляется функцией от таблицы манифеста при каждой записи, а не только на этапе спецификации. Правка манифеста после `spec` не оставляет G1 красным или зелёным по устаревшим данным. (Именно это остановило R22d на `finish`.)» — R09
> «B2. `ticket NN done` без `--commit` (и без ранее записанного коммита) отказывает. Отказ git при коммите это сбой машины: `ticket NN fail --note`, вопрос пользователю, не ремонт.» — R10
> «B3. `finish` отказывает при: незакрытом G1–G4, таске не в `done`, таске без коммита, коммите не из `HEAD`. Это добавляется к уже существующим проверкам блокеров, подписи и отпечатка плана, а не заменяет их.» — R11
> «B4. Сдать с отказами можно только `finish --result "…" --by-user "<цитата>"`. В `state.js` пишется `landedWith`, строка реестра «сдан с оговорками», шапка дашборда «Сдано с оговорками».» — R12
> «B5. Расхождения слепой приёмки, оставшиеся после двух кругов, сдаются с той же оговоркой, а не блокируют `finish`.» — R13
> «B6. В preflight git проверяется до брифинга (`git add -- .gitignore` или эквивалент без побочных эффектов). Отказ записи останавливает прогон сразу, с понятной причиной, а не на первом таске.» — R14

## Критерии приёмки

- [ ] `ticket NN reset` на таске в статусе `failed` без `--by-user` — отказ с текстом «упал — дальше решает пользователь»; с `--by-user "<цитата>"` — статус `pending`, `repairs == retries == 0`, цитата в `reopenedByUser` и в журнале; `reset` не упавшего таска работает как раньше
- [ ] третий `ticket NN repair` и третий `ticket NN retry` отклоняются (тест на оба; поведение уже есть), текст отказа называет `ticket NN fail --note` и вопрос пользователю
- [ ] `retry --cause environment` не разрешён политикой (тест в `test_retry_policy.py` или `test_ap.py`; если политика позволяет — исправить)
- [ ] третий `ap.py blind checked=… matched=…` отклоняется и не меняет `state.blind` и гейт G4; `blindRounds` растёт на 1 только после успешной записи; `reopen` обнуляет `blindRounds`
- [ ] после `stage spec done` строка манифеста открыта вручную → следующая записывающая команда `ap.py` ставит G1 красным; закрыта → зелёным (тест, оба направления)
- [ ] `ticket NN done` без `--commit` и без записанного `tk.commit` отклоняется; текст говорит «сбой машины, не ремонт» и называет `ticket NN fail --note` (тест)
- [ ] `finish` без `--by-user` отказывает при каждом из: G1–G4 не ok, таск не `done`, `done` без коммита, коммит `done`-таска вне HEAD, нет успешных тестов (по тесту на условие), текст называет `finish --result … --by-user`
- [ ] `finish --result … --by-user "<цитата>"` проходит эти отменяемые проверки, пишет `state.landedWith = {problems, byUser}` и строку «сдан с оговорками» в `.autopilot/README.md`; без проблем `landedWith` не пишется и строка «сдан»
- [ ] неотменяемые проверки (подделка записи гейтов, открытый `blockingFindings`, смена `planContractDigest`, красный `check_plan`) отказывают и с `--by-user` (по тесту на условие)
- [ ] G4 красный при `blindRounds >= 2` не блокирует `finish` и без `--by-user`: `landedWith.problems` содержит строку про расхождения (тест)
- [ ] `ap.py git-check` при занятом `.git/index.lock` печатает «git не может писать здесь…» и завершается кодом 2; при исправном git печатает «git: запись разрешена» и код 0; не требует `state.js` (тест)
- [ ] все ранее существующие тесты проходят; добавленные тесты лежат рядом с кодом
