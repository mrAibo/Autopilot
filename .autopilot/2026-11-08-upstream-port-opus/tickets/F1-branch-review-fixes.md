## Критерии приёмки (находки ревью дословно)

- [ ] 1. `ap.py:2728-2753` + `phases/0-preflight.md:33` — `git-check` берёт ROOT как родителя каталога скрипта; preflight идёт до копирования инструментов, а копия из `skills/.../tools` проверяет каталог навыка (при установке в `~/.claude/skills` это не репозиторий пользователя) и ложно отвечает «git не может писать здесь» (код 2). Условие: команда проверяет git из cwd (`rev-parse --show-toplevel`), preflight запускает копию из `tools/` навыка; тест, где ap.py лежит вне репозитория и запускается из cwd репозитория.
- [ ] 2. `phases/5-repair.md:7`, `phases/4-plan.md:74`, `CHANGELOG.md:16`, `ap.py:1699-1745` — вопрос «ремонт на Opus?» ни к чему не ведёт: `opusAgents` создаются только в `plan-models --apply` при непустом подтверждении, `ticket F route` на Opus-ремонт не сделан. Условие: вопрос задаётся только при наличии `state.opusAgents`; `opus approve --roles …` без `opusAgents` печатает `!`-предупреждение (тест); Opus-ремонт назван в CHANGELOG и в «Известных ограничениях» нерабочим, пока `route` его не назначает. Новых возможностей не добавлять.
- [ ] 3. `phases/4-plan.md:74` vs `ap.py:133-163` — текст говорит, что `opus propose` печатает и роли `repair`/`reviewer`, команда печатает только таски. Условие: `propose` печатает роли или текст перестаёт их обещать (выбери меньшее).
- [ ] 4. `phases/8-final.md` шаг 2 «Landing with caveats» — «пользователь может снять G4-расхождение, открытый concern» не совпадает с `landing_problems` (`ap.py:2541-2578`): `concerns` finish не проверяет, G4 после двух кругов проходит сам. Условие: текст перечисляет именно снимаемое — G1–G4, таск не `done`, нет коммита, коммит вне HEAD, нет тестов, открытые строки манифеста.
- [ ] 5. `phases/5-repair.md:5` — «reset --by-user works on a failed ticket too» читается как «снимает лимит и на не упавшем таске»; код обнуляет счётчики только у `failed` (`ap.py:1836-1840, 2090-2093`), и третий `repair` снова откажет. Условие: текст говорит «сначала `ticket NN fail`, потом `reset --by-user`».
- [ ] 6. Полный `python -m unittest discover -s tests` зелёный; поведение по умолчанию без `--by-user` и без подтверждения Opus не меняется.
