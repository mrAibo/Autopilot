# Спецификация: порт апстрима 2.2.2/2.2.3 и точечный Opus

## Задача
Сборка не должна ходить кругами и не должна называться «сданной», когда это не так; дорогую модель включает только пользователь. Апстрим nick-vels/skills (2.2.2, 2.2.3) решил первое, мы портировали только до 2.2.1. Opus сейчас закрыт целиком; пользователь хочет включать его точечно (подтверждение пользователя, Fable остаётся закрытым).

## Решение
Прогон, который упёрся в лимиты, останавливается и спрашивает пользователя; «сдан» значит сдан, а не сдан-как-есть-молча; G1 всегда равен состоянию манифеста. В плане Autopilot предлагает таски, где Opus уместен, пользователь подтверждает список цитатой — и только они (и ремонт/ревью ветки, если разрешено) идут на Opus. Без подтверждения всё как сегодня.

## Решения по реализации
Команды `opus …`, `git-check`, `refresh_g1`, `BLIND_ROUNDS`, поля `opusApproval`/`opusAgents` и порог `risk >= 10` — средства для R03/R04/R09/R14/R17/R18 (порог берётся из существующего `assess_scores`, где `risk >= 10` уже поднимает профиль до strong); отдельных требований они не добавляют.

### 4.0 Принцип порта (R01)
Фиксы апстрима переписываются под наш `ap.py`. Нельзя ломать: подпись гейтов, `blockingFindings`, `planContractDigest`, маршруты. Апстримные имена не обязательны, обязательны поведение и один регрессионный тест на пункт.

### 4.1 Счётчики и `reset` (R02, R03, R06)
- `repairs`/`retries` ≥ 2 → отказ уже есть. Менять только текст отказа: назвать `ticket NN fail --note "что блокирует"`, затем вопрос пользователю.
- `reset`: если `tk.status == "failed"` и нет `--by-user` (непустая строка) → `die` с текстом «таск NN упал — дальше решает пользователь…». С `--by-user`: как обычный `reset`, плюс `tk["reopenedByUser"].append(цитата)`, `repairs = retries = 0`, цитата в журнале (`ticket-reset`, `reason="by-user"`).
- `reset` не упавшего таска (синхронизация после rebase, `0-resume.md`) — без изменений.
- Сбой окружения (таймаут, нативный модуль, порт, путь только на этой машине) — `fail`, не ремонт: правило в `phases/5-repair.md`; в коде проверить, что `retry_policy.decide("environment", …)` не разрешает повтор, и покрыть тестом.

### 4.2 Круги слепой приёмки (R04)
`BLIND_ROUNDS = 2`. `state["blindRounds"]` (int, по умолчанию 0). `cmd_numbers blind`: если `blindRounds >= BLIND_ROUNDS` → `die` (подсказка: `add report "…"`, остаток идёт в отчёт); иначе записывает как сейчас и `blindRounds += 1`. `cmd_reopen` обнуляет. Вызов, упавший с ошибкой до записи, счётчик не трогает.

### 4.3 G1 за манифестом (R09)
Новая `refresh_g1(state, create=False)`: если G1 в `gates` нет и `create=False` — выход; иначе пересчитать `open` по `manifest_table` (строки не `D`) и вызвать `set_gate(G1, open==0, open=n, total=…)` только при смене. Вызывается: в `cmd_stage` (заменяет текущий блок для `spec`), в `check-plan`/`tickets`, в `cmd_finish` (`create=True`, до проверки гейтов) и в **общей точке записи состояния** (функция сохранения, через которую идут все записывающие команды): G1 пересчитывается при каждой записи, если он уже есть в `gates`. Если такой общей точки нет, исполнитель заводит её минимально и записывает это в `interfaces.md`.

### 4.4 `done` без коммита (R10)
Поведение уже верно. Менять только сообщение: когда `--commit` не передан и `tk.commit` пуст — «нет --commit… отказ git — сбой машины, не ремонт: `ticket NN fail --note`»; тест.

### 4.5 `finish`, оговорки, дашборд (R11–R13, R15)
- Разделить проверки `cmd_finish` на **неотменяемые** (подпись гейтов `gate_signed`, открытые/старые `blockingFindings`, resolved-блокеры с коммитом вне HEAD, смена `planContractDigest`, красный `check_plan`) и **отменяемые** (G1–G4 не ok; таск не `done`; `done` без `commit`; коммит `done`-таска вне HEAD; нет тестов или красные; открытые строки манифеста). Все существующие проверки остаются — меняется только то, что отменяемые собираются в список `refuse`.
- G4 красный при `blindRounds >= BLIND_ROUNDS` → не в `refuse`, а в `caveat` (R13).
- `refuse` непустой и нет `--by-user` → `die` со списком и подсказкой `finish --result "…" --by-user "<цитата>"`.
- Есть `refuse` (с `--by-user`) или `caveat` → `state["landedWith"] = {"problems": [...], "byUser": цитата|None}`; `register_row(state, "сдан с оговорками", result)`; печать `! сдано с оговоркой — …`; в `log` запись `finish` с `problems=N`. Нет проблем → `landedWith` не пишется, строка «сдан».
- Дашборд: если `S.landedWith` — вместо зелёной шапки «Сдано» шапка «Сдано с оговорками» (предупреждающий цвет из палитры темы, не красный), под ней список `problems`. Строки i18n RU/EN как остальные. Живой `.autopilot/dashboard.html` обновляется `dashboard_upgrade.py`.

### 4.6 `ap.py git-check` (R14)
Команда без побочных эффектов на содержимом: `git update-index -q --refresh` в корне проекта (создаёт и снимает `index.lock`, то есть проверяет возможность записи; содержимое индекса и файлы не меняет — эквивалент `git add -- .gitignore` из брифа без побочных эффектов). Любой отказ (`index.lock`, `Permission denied`, `read-only`, sandbox) → сообщение «git не может писать здесь: <первая строка ответа>. Это сбой машины, не кода», код возврата 2. Успех → `git: запись разрешена`. Не заводит `state.js` и не требует `init`. `phases/0-preflight.md` §2: вызвать до `init`; отказ — остановка прогона с этим текстом.

### 4.7 Opus (R16–R22, G01)
Принцип: Opus существует только как подтверждённый пользователем исключительный маршрут; по умолчанию и без подтверждения все пути идут как сегодня. Fable и Astra — всегда закрыты.

- **`model_router.py`**
  - `is_opus_model(name)`: `normalize_model_name` даёт семейство `opus`, не `fable`.
  - `is_allowed_subagent_model(name, premium_ok=False)`: по умолчанию поведение прежнее; при `premium_ok=True` дополнительно допускает `is_opus_model(name)`; Fable — никогда.
  - В `DEFAULT_POLICY.providers.anthropic` ключ `premium: {model: "opus", effort: "high"}` (профиль не выбирается `assess_scores`).
  - `choose_route(..., premium=False)`: при `premium=True` и провайдере anthropic возвращает premium-профиль и не считает Opus «restricted»; при `premium=False` — как сегодня.
  - `premium_candidate(route_or_scores)`: `True`, если `risk >= 10` или `profile == "critical"`.
- **Файл таска**: поле `**Модель:** opus` (регистр не важен) — предложение (кандидат), в `tk["model"]` уже разбирается. Причину оркестратор пишет в той же строке: `**Модель:** opus — <причина>`. Действует только при подтверждении.
- **`ap.py opus`**:
  - `opus propose` — читает pending-таски, перечисляет кандидатов (по пометке и по `premium_candidate`), для каждого: id, название, причина, строка «дороже Sonnet-таска, не измерено». Только печать.
  - `opus approve [--tickets 03,05] [--roles repair,reviewer] --by-user "<цитата>"` — обязательны цитата и хотя бы один из `--tickets/--roles`; пишет или расширяет `state["opusApproval"] = {"tickets": [...], "roles": [...], "quotes": [{"at": …, "quote": …}], "sig": …}`; `sig` — `gate_sign.sign` над `{"tickets", "roles"}`; в strict-прогоне (там ключ обязателен) без подписи `approve` отказывает, в прогоне без ключа `sig = null` и guard такое подтверждение не принимает. Неизвестный id таска → отказ. Роль вне `repair|reviewer` → отказ. Запись в `log`.
  - `opus status` — печатает текущее подтверждение.
- **`plan-models --apply`**: таски из `opusApproval.tickets` маршрутизируются `choose_route(premium=True)`; остальные как сегодня. Если `opusApproval` не пуст, дополнительно создаются профили `autopilot-reviewer-opus-<run>` и `autopilot-executor-repair-opus-<run>` (закреплённые файлы в `.claude/agents/`, как все остальные профили прогона: `model: opus` и `effort` закреплены, `profileSha` и проверки guard остаются), в state: `opusAgents = {"reviewer": имя, "repair": имя}`. Нет подтверждения — ничего из этого не создаётся.
- **`claude_agent_guard.py`**: перед проверкой `is_allowed_subagent_model(model)` вычислить `premium_ok`: профиль opus и в `state["opusApproval"]` подпись верна (в подписанном прогоне `gate_sign.verify`) и (a) executor: id таска маршрута в `opusApproval.tickets`, либо (b) `name == opusAgents.reviewer` и `"reviewer"` в `roles`, либо (c) `name == opusAgents.repair` и `"repair"` в `roles`. Иначе отказ с прежним текстом. Остальные проверки (pinned model, capabilities, profileSha, подпись маршрута) не ослабляются. Тест «в guard нет приватного списка премиум-моделей» остаётся верным (guard использует общую функцию).
- **`claude_attest.py` / `check_claude_attestation`**: без изменений; Opus сверяется как любая модель (`fits`).
- **`agent_profiles.py`**: `prepare(…, premium=False)` пробрасывается в `choose_route`; других изменений нет.
- **Вопросы пользователю**: (1) в плане (`phases/4-plan.md` «Showing the plan»): список `opus propose`, вопрос «включить Opus для этих тасков? дороже Sonnet-таска, не измерено», ответ → `opus approve`; (2) в разработке (`5-repair.md`, `6-review.md`): вопрос одной строкой в момент появления кандидата и только если профили `opusAgents` заведены. Кандидаты: ремонт таска, у которого `repairs >= 2` (ремонт дважды вернулся с ревью), и общее ревью ветки, если `git diff --shortstat <baseCommit>..HEAD` даёт больше 3000 изменённых строк (граница из правила размера таска). «Да» → `opus approve --roles repair|reviewer --by-user …`; назначение профиля — существующим `ticket NN route`; если `route` не умеет назначать профиль не-F таску, ограничиться F-тасками и записать это в «Известные ограничения» сдачи. Нет `opusAgents` — вопроса нет, всё идёт обычным профилем.
- **Отчёт и дашборд** (R22): `8-final.md` — список тасков и ролей на Opus и фактическая стоимость по `skills/autopilot/tools/measure-run.py` (брифа C7), время и токены по `ap.py report-run`; вид `models` показывает строку из `S.opusApproval` (цитата, таски, роли), чип модели на таске уже показывает `routing.model`.
- **Обновление договорённости**: в `PROGRESS.md` при сдаче строка «Opus и Fable не допускаются… R06, R18» заменяется на «Opus допустим для субагентов только по подтверждению пользователя (`opusApproval`), Fable закрыт — R16–R22 этой сборки».

### 4.9 Ограничения и критерии (R23–R32)
- **R23** все 669 существующих тестов остаются зелёными на Python 3.11 и 3.13 (меняются только перечисленные в `notes.md`, и только в сторону «без подтверждения не проходит»; их число может вырасти за счёт новых).
- **R24** требование из `manifest.md` снимает только пользователь: сборка не вводит способа снять требование без его слов; `--by-user` фиксирует слова пользователя, но не снимает строки манифеста.
- **R25** секреты не запрашиваются и не пишутся: ни в `--by-user`, ни в `opusApproval`, ни в журналы; цитата проходит тот же редактор секретов, что и бриф (`phases/1-manifest.md`).
- **R26** поведение по умолчанию не меняется, кроме новых отказов R03, R04, R10, R11 (они и есть смысл брифа).
- **R27** `state.js` пишется только через `state_io.py`; новых инструментов-файлов нет, поэтому списки копирования в харнессах не меняются.
- **R28** README и документация правятся только там, где поведение изменилось; если README упоминает «Opus закрыт», правка идёт синхронно в `README.md`, `README.ru.md`, `README.de.md`.
- **R29** `python -m unittest discover -s tests` зелёный на 3.11 и 3.13.
- **R30** по одному регрессионному тесту на каждый пункт A1–A3, B1–B5, C6.
- **R31** слепая приёмка идёт по брифу, спецификация от неё скрыта.
- **R32** запись в `CHANGELOG.md` о порте и об Opus с честной пометкой, что экономия Opus-субагентов не измерена.
