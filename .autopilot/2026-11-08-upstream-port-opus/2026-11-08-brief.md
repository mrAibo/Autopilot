# Бриф: порт апстрима 2.2.2 и 2.2.3 + точечное включение Opus

Режим: `interview` (по блоку C), блоки A и B без вопросов. Глубина: `strict`.
Запускать после слияния PR 81 в `main`, из свежей ветки от `main`.

## Зачем

Сборка не должна ходить кругами и не должна называть себя «сданной», когда это не так. Дорогие и зацикленные решения принимает пользователь, а не оркестратор. Апстрим nick-vels/skills ушёл на 2.2.3 (2026-11-05), мы портировали только до 2.2.1.

Портировать нужно не копированием: наш `ap.py` разошёлся с апстримом (подписанные гейты, блокеры, маршрутизация). Каждый фикс переписывается под наш код с одним регрессионным тестом (как в порте 2.2.1, коммиты `a436a78`).

## Блок A — порт 2.2.2 («сборка останавливается, а не ходит кругами»)

- A1. `ap.py` отказывает в третьем `ticket NN repair` и третьем `ticket NN retry` (лимит 2 на каждый). Отказ даёт команду, а не только текст фазы.
- A2. Упавший таск (`failed`) снова идёт в работу только через `ticket NN reset --by-user "<цитата пользователя>"`. Цитата пишется в таск (`reopenedByUser`) и в журнал, счётчики `repairs` и `retries` обнуляются. `reset` без `--by-user` на упавшем таске отказывает.
- A3. Слепая приёмка: не больше двух кругов за прогон (проверка, таск `F2`, одна перепроверка). Счётчик `blindRounds`, сбрасывается в `reopen`. Третий `blind` отказывает с подсказкой `add report` для остатка.
- A4. В `phases/4-plan.md`: таски, которые только проверяют («подтвердить готовность», «прогнать полную проверку»), запрещены.
- A5. В `phases/5-repair.md`: сбой окружения (таймаут, не грузится нативный модуль, порт, неработающий сервис, путь только на этой машине) это `fail` с вопросом пользователю, а не ремонт.
- A6. В `phases/8-final.md`: «один круг исправлений, потом отчёт, третьего взгляда нет».
- A7. После сжатия контекста оркестратор перечитывает и `5-repair.md` (правка в `SKILL.md`).

## Блок B — порт 2.2.3 («Сдано» значит сдано)

- B1. G1 идёт за манифестом: вычисляется функцией от таблицы манифеста при каждой записи, а не только на этапе спецификации. Правка манифеста после `spec` не оставляет G1 красным или зелёным по устаревшим данным. (Именно это остановило R22d на `finish`.)
- B2. `ticket NN done` без `--commit` (и без ранее записанного коммита) отказывает. Отказ git при коммите это сбой машины: `ticket NN fail --note`, вопрос пользователю, не ремонт.
- B3. `finish` отказывает при: незакрытом G1–G4, таске не в `done`, таске без коммита, коммите не из `HEAD`. Это добавляется к уже существующим проверкам блокеров, подписи и отпечатка плана, а не заменяет их.
- B4. Сдать с отказами можно только `finish --result "…" --by-user "<цитата>"`. В `state.js` пишется `landedWith`, строка реестра «сдан с оговорками», шапка дашборда «Сдано с оговорками».
- B5. Расхождения слепой приёмки, оставшиеся после двух кругов, сдаются с той же оговоркой, а не блокируют `finish`.
- B6. В preflight git проверяется до брифинга (`git add -- .gitignore` или эквивалент без побочных эффектов). Отказ записи останавливает прогон сразу, с понятной причиной, а не на первом таске.
- B7. Дашборд (`phases/dashboard-template.html`) показывает «Сдано с оговорками». Живые проекты обновляются `dashboard_upgrade.py`, `.autopilot/dashboard.html` не копируется вручную.

## Блок C — точечное включение Opus для субагентов

Сейчас Opus и Fable не проходят `model_router.is_allowed_subagent_model` ни в каком написании. Это защита, и её нельзя превратить в обычную настройку.

- C1. По умолчанию ничего не меняется: Opus выключен, поведение и тесты «Opus не проходит» остаются, пока нет подтверждения.
- C2. Включение явное и на прогон: на этапе плана Autopilot показывает список тасков, где Opus уместен, и цену, пользователь отвечает да или нет. Ответ записывается в `state.js` вместе с цитатой, подписанно, как гейты.
- C3. В роутере отдельный уровень выше «сильной». Выбирается только для тасков с высоким риском (безопасность, конкурентность, миграции данных) или с явной пометкой в файле таска, и только при подтверждении по C2.
- C4. Кандидаты помимо рискованных тасков: ремонт, дважды вернувшийся с ревью; общее ревью ветки на большом диффе.
- C5. Нужно согласовать с `claude_agent_guard.py`, `claude_attest.py` и закреплёнными профилями в `.claude/agents/`: что в attest считается допустимой моделью, как guard проверяет подтверждение.
- C6. Тесты переписываются из «Opus не проходит» в «Opus не проходит без подтверждения, и проходит только для помеченного таска при подписанном подтверждении». Отдельный тест на поддельное подтверждение.
- C7. Дашборд и отчёт показывают, какие таски шли на Opus и сколько это стоило по `measure-run.py`.

Открытые вопросы для `interview`: порог риска или пометка в таске, или оба; кто решает «рискованный» (скоринг роутера или человек); подтверждение на весь прогон или по таскам; как показывать цену, пока нет измерения Opus-субагентов.

## Что нельзя ломать

- Все 669 тестов остаются зелёными, добавленные тесты идут вместе с кодом.
- Требование из `manifest.md` снимает только пользователь.
- Секреты не запрашиваются и не пишутся.
- Поведение по умолчанию (без `--by-user`, без подтверждения Opus) в рабочих прогонах не меняется, кроме новых отказов из A1, A3, B2 и B3: они и есть смысл брифа.
- `state.js` пишется только через `state_io.py`; харнессы, копирующие `ap.py`, копируют `state_io.py`, `process_containment.py`, `run_log.py`.
- README и документацию правим только там, где поведение изменилось (`CHANGELOG.md`, `docs/autopilot/`, три языка там, где нужно).
