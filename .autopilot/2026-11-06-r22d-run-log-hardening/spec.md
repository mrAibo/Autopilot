# Спецификация: журнал надёжнее (R22d)

## Задача
Журнал прогона (`run-log.jsonl`) сдан в прошлой сборке, но при поломке молчит: без `run_log.py` пользователь видит «журнал пуст» и не знает, что его просто не пишут; список копирования модулей держится на ручной аккуратности; одна испорченная вручную строка или запись без номера прогона портит свод; роль субагента в журнале всегда «исполнитель».

## Решение
- **R22q** Без `run_log.py` (не импортируется) любая команда `ap.py` печатает в stderr одну строку: «`run_log.py` не найден, журнал не пишется» (при ошибке внутри самого модуля — «`run_log.py` не импортируется (<тип ошибки>), журнал не пишется»). Раз за запуск; команды работают как раньше.
- **R22r** `ap.py report-run` без модуля печатает «журнал недоступен: `run_log.py` не найден, журнал не пишется» (не «журнал пуст»), код выхода 0. «Журнал пуст» остаётся только для работающего модуля без записей.
- **R22s** Тест: каждый модуль из `tools/`, который импортирует `ap.py`, перечислен в `0-instruments.md`; плюс каждый файл `tools/*.py` либо перечислен там, либо назван в явном списке в тесте «запускается из навыка» — новый модуль, не попавший ни туда, ни сюда, красит тест. Динамические импорты тест не видит (предел, в комментарии).
- **R22t** `read_all_stats(dir) -> (rows, skipped)` считает нечитаемые JSON-строки; `summarize` пропускает строки с неверной структурой (`k` не строка или неизвестен, значение поля — список/словарь) и считает их; свод и `--share` печатают «пропущено испорченных строк: N», если N > 0. `report-run` не падает ни на какой строке журнала.
- **R22u** `report-run` берёт прогон последней записи с непустым `run`; записи без `run` в свод прогона не попадают. Если ни у одной записи нет `run` — одна строка «в журнале нет записей с номером прогона», код 0.
- **R22v** Строка исполнителя получает поле `role`: `executor` | `reviewer` | `explorer` | `acceptance` по имени профиля (`autopilot-<роль>-…`; ремонтный исполнитель — `executor`), иначе `agent`. Вид строки `k:"executor"` не меняется (старые журналы читаются). `report-run`: колонка «роль», в `--share` роль без слага профиля.
- **R22w** Тесты на пункты R22q–R22v и запись в `CHANGELOG.md`; `docs/autopilot/run-log.md` дополнен (поле `role`, строка пропущенных, предупреждение).

## Инварианты
- Поведение шлюзов G1–G4 и независимой приёмки не ослабляется; `claude_agent_guard`, `spend_guard`, `test_evidence` не ослабляются ради удобства.
- Требование из брифа может снять только пользователь; эта сборка не снимает ни одного.

## Решения по реализации
- Роль — поле строки, а не новый вид `k`: `executor` уже в схеме, журналы прошлой сборки и тесты остаются читаемыми. Роль считается в `claude_attest.log_usage` (`run_log.role_of`), а для старых строк без `role` отчёт восстанавливает её тем же регэкспом из `agent_type`.
- Предупреждение в stderr, не в stdout: не ломает разбор вывода команд и тестов.
- Пропуск испорченного — предварительная проверка строки плюс страховочный `try/except` вокруг разбора одной строки: журнал только читается, отчёт не должен падать.
- Строка о пропущенных пишется и в `--share` (число — не данные проекта).
