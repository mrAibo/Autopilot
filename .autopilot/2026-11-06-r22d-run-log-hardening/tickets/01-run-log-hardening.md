# 01 — Журнал надёжнее

**Требования:** R22q, R22r, R22s, R22t, R22u, R22v, R22w
**Зависит от:** —
**Зона:** `skills/autopilot/tools/run_log.py` · `skills/autopilot/tools/ap.py` · `skills/autopilot/tools/claude_attest.py` · `docs/autopilot/run-log.md` · `CHANGELOG.md` · `tests/test_run_log.py` · `tests/test_ap.py` · `tests/test_claude_attest.py` · `tests/test_state_io.py`
**Волна:** 1
**Ревью:** нет
**Модель:** обычная

## Что должно заработать

Журнал прогона перестаёт молчать при поломке и не портит свод: без `run_log.py` `ap.py` говорит об этом одной строкой, а `report-run` не выдаёт это за «журнал пуст»; список копирования модулей проверяется тестом по всем модулям `tools/`; свод переживает испорченные строки и записи без `run`; в строке исполнителя есть роль субагента.

Читать сначала: `interfaces.md`, `spec.md` (разделы «Решение», «Инварианты», «Решения по реализации»), `notes.md` — в папке прогона.

## Из брифа, дословно

> «Если `run_log.py` не импортируется, `ap.py` пишет одну строку предупреждения («`run_log.py` не найден, журнал не пишется»), а `report-run` не говорит «журнал пуст» (`ap.py:62`, `ap.py:2646`). Команды при этом не ломаются.»
> «Тест на список копирования: модули, которые импортирует `ap.py` из `tools/`, перечислены в `phases/0-instruments.md`; пропуск ловится тестом. Модули, которые намеренно запускаются из навыка, перечислены в тесте явно.»
> «`report-run` не падает на вручную испорченных строках журнала (пропускает с отметкой числа пропущенных); запись без поля `run` не склеивает все прогоны в один свод.»
> «Роль субагента в журнале берётся из его профиля (`executor`, `reviewer`, `explorer`, `acceptance`), а не всегда `executor`; нужна для R26.»
> «Тесты на каждый из четырёх пунктов; запись в `CHANGELOG.md`.»

## Критерии приёмки

- [ ] В харнессе `ap.py` без `run_log.py` любая команда (например `tests 1/0`) печатает в stderr ровно одну строку «`run_log.py` не найден, журнал не пишется», код выхода и результат команды те же, что с модулем (тест); при ошибке внутри модуля строка называет тип ошибки
- [ ] Без `run_log.py` `report-run` печатает «журнал недоступен: …не найден, журнал не пишется», не «журнал пуст», код 0; с модулем и без записей печатается «журнал пуст» (тест)
- [ ] Тест в `tests/test_state_io.py`: каждый `tools/*.py` либо перечислен в `0-instruments.md`, либо назван в явном списке `RUN_FROM_SKILL` в тесте; модуль, не попавший ни туда, ни сюда, красит тест (проверить на временной копии списка); все модули, что импортирует `ap.py` из `tools/`, перечислены
- [ ] `report-run` на журнале с обрезанной JSON-строкой, строкой с `id` списком, `cause` не строкой и неизвестным `k` не падает и печатает «пропущено испорченных строк: N» с верным N; то же в `--share` (тест)
- [ ] Журнал с записями двух прогонов, где последняя запись без `run`: свод — по прогону последней записи с `run`, записи без `run` в него не входят; журнал, где ни у одной записи нет `run` — одна строка «в журнале нет записей с номером прогона», код 0 (тест)
- [ ] `claude_attest.log_usage` для `autopilot-reviewer-x`, `autopilot-explorer-x`, `autopilot-acceptance-x`, `autopilot-executor-x`, `autopilot-executor-repair-x` пишет `role` `reviewer`/`explorer`/`acceptance`/`executor`/`executor`; чужое имя — `agent`; `report-run` показывает колонку «роль», старые строки без `role` получают роль из `agent_type` (тест на каждый случай)
- [ ] Запись о R22d в `CHANGELOG.md`; `docs/autopilot/run-log.md` описывает поле `role`, строку пропущенных и предупреждение; тест на пары локалей зелёный
- [ ] Тест `test_no_machine_data` зелёный (в новых тестах нет литералов путей машины)
- [ ] Полный прогон `python3 -m unittest discover -s tests` зелёный
