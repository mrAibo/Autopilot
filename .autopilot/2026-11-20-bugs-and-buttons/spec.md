# Спецификация: баги ревью и кнопки подтверждения

## Задача
Закрыть три слабых места ревью и дать пользователю отвечать агенту кнопкой на дашборде, не переписывая ответ в чат. Требования из брифа: R01–R03 (баги), R33–R35 (кнопки, «Волна 2»), R04 и R36 — что не трогать.

## Решение

**Баги.**
- R01: в неизолированном прогоне зависимый от родителя в `review` не блокируется как `overlapping-zone` зоной этого родителя (код родителя закоммичен, зависимый строится поверх него); зоны других таксов в работе блокируют, как раньше; зависимость в `in-progress`, `repair`, `failed`, `pending` по-прежнему блокирует; в изолированном прогоне правило прежнее (нужен `done`, `review` держит зону).
- R02: `commit_paths` с каталогом в `paths` берёт старый путь переименования только при сходстве 100% (`R100`): чужое индексное удаление, лишь похожее на новый файл каталога, остаётся в индексе. Дословный путь работает как раньше (любое сходство). Тест «`dir` не захватывает `dir2/…`» и тест на похожее, но не идентичное удаление.
- R03: после успешного `ensure_key` над целым ключом брошенная заявка `gate.key.claim` не остаётся молча: `ensure_key` ещё раз пробует её снять, а если не вышло — печатает одну строку на stderr с её именем и словом «удали». Новый тест через `busy_claim` над целым ключом: ключ тот же, судьба заявки проверена.

**Кнопки.**
- R33: ADR `docs/adr/0015-dashboard-actions.md` — как агент узнаёт о нажатии: команда `ap.py await [--timeout N]` (код 0 — ответ получен, 3 — нет ответа за срок, 4 — ничего не ждём), что делать при закрытой вкладке (агент после срока спрашивает в чате; ответ в чате закрывает ожидание как раньше). Один маршрут `POST /.ap-act` в `make_server` с проверками токена, Host, Origin, `Sec-Fetch-Site`, размера; всё прочее на `POST` — 405.
- R33.2: нажатие исполняется теми же функциями, что CLI (`close_wait`, `log`, `save`, `write_snapshot`; закрытие ожидания — то же, что в `cmd_ask`/`answered`) под `state.lock` и через `state_io`; в журнале строка `answered` с `source=dashboard`; страница `state.js` не пишет.
- R34: кнопки только на четырёх ожиданиях — `briefing` (поле ответа, не пустое), `spec`, `plan`, `accept` (новый вид: «принять сдачу»; фазы вызывают `ask accept` только в режиме `manual` после отчёта, прежний ход сборки не меняется). Кнопка называет действие и просит второе нажатие. Ожидания `action` и `stop` кнопок не имеют.
- R34.1: действия со словами пользователя (`ticket NN reset --by-user`, `finish --by-user`, `opus approve --by-user`, снятие требования `dropped`) не кнопки: страница показывает готовую команду с местом `<цитата>` и кнопкой «скопировать».
- R34.2: список разрешённых действий `ALLOWED_ACTIONS` — константа в `ap.py` и в тесте; новое действие без записи в обоих падает; `stop`, `action`, `finish`, `opus`, `reset`, `dropped`, подписи, ключ, `blind` через `/.ap-act` — 403.
- R35: блок кнопок рисуется одним кодом для шести дизайнов, дизайны меняют только вид.
- R35.1: `file://` или без токена кнопок нет — одна строка «открой адрес из `ap.py url`»; ошибка сервера — кнопка возвращается, строка с причиной.
- R04, R36: R28 и всё из раздела «Чего в этом брифе нет» не трогаются: шлюзы, подписи, guard, слепая приёмка, Opus/Fable, дифф и «план → факт» на странице.

## Решения по реализации
- **Ответ не попадает в `state.js`.** Он ложится в `.autopilot/serve.answer.json` (попадает под `serve.*` в `.gitignore`, не коммитится); `await` читает и удаляет его. В `state.js` только `waits` и строка журнала (вид, `source`), без текста: ответ может содержать секрет, а `.autopilot/` коммитится. Ответ перед записью проходит ту же редакцию секретов, что бриф (`phases/1-manifest.md` §1), и режется до 2000 знаков.
- **Привязка к конкретному ожиданию.** В запросе `since` ожидания; не совпал — 409 `stale`; нет ожидания — 409 `no-wait`; другой вид — 409 `other-kind`. Одновременное нажатие и CLI: выигрывает первый под `state.lock`, второй получает 409.
- **Блокировка.** Сервер берёт `locked_state(timeout=10)`; занято — 503 `busy`, кнопка возвращается.
- **`await` не держит `state.lock`.** Он обрабатывается вне блока `locked_state` (как `--serve`), читает `state.js` без записи раз в секунду; `--timeout` по умолчанию 300, не больше 3500.
- **Коды ответов `POST /.ap-act`:** 200 `{"ok":true}`; 400 битый JSON или поля; 403 токен/Host/Origin/`Sec-Fetch-Site`/запрещённое действие (тело не разбирается); 405 любой другой `POST`-путь; 409 `no-wait|other-kind|stale`; 413 тело больше 8 КБ (по `Content-Length`, до чтения); 503 `busy`. `Origin` для `POST` обязателен и равен `http://<Host>`; `Content-Type: application/json`.
- Тексты фаз: строка про `await` и вид `accept` в `phases/0-instruments.md`, пара слов в `2-briefing.md`, `3-spec.md`, `4-plan.md`, `8-final.md`; `tests/test_text_split.py` не должен покраснеть.
- Каждый баг — регресс-тест; запись в `CHANGELOG.md` («Unreleased») на каждый из шести пунктов; AGENTS.md — строка про `await` и кнопки.

## Тесты, которые обязаны быть (из «Готово, когда» брифа)
- **Сервер (R33, R34.2):** чужой Origin и отсутствие Origin — 403; неверный и отсутствующий токен — 403; `Sec-Fetch-Site: cross-site` — 403; действие без ожидания — 409 `no-wait`; не тот вид — 409 `other-kind`; устаревший `since` — 409 `stale`; одновременное нажатие и команда CLI (`answered`) — один выигрывает, второй 409; тело больше 8 КБ — 413 до чтения; пустой ответ для `briefing` — 400 (для остальных видов поле не нужно); прочие `POST`-пути — 405. Тест перечисляет `ALLOWED_ACTIONS` и падает при новом действии без записи; `stop`, `action`, `finish`, `opus`, `reset`, `dropped`, подпись/гейт, повышение модели, `blind` через `/.ap-act` — 403 и в `state.js` после них ничего не изменилось (гейты, модель, слепая приёмка нетронуты). Нажатие пишет `answered` с `source=dashboard`, `await` отдаёт ответ из дашборда и удаляет файл; закрытое ожидание не оставляет `serve.answer.json`.
- **Страница (R35, R35.1):** во всех шести дизайнах блок кнопок рисуется одним кодом; при пустом `waiting` кнопок нет; на `file://` и без токена кнопок нет и есть строка про `ap.py url`; ответ сервера не 200 или сеть/остановленный сервер (`fetch` отклонён) — кнопка возвращается и показывает причину, страница не падает; для `briefing` пустое поле — кнопка не отправляет; второе нажатие обязательно.

## Вне рамок
| Требование | Почему не сейчас |
|---|---|
| кнопки «отклонить»/правка спецификации | возражение пишется в чате; кнопка — только «ок» |
| несколько вкладок с общим состоянием | первый выигрывает, второй получает 409 |
| `await` как фоновая служба хоста | `await` — обычная команда; хост запускает её в фоне |
| том без жёстких ссылок (`os.link`) | прежнее ограничение, остаётся в `PROGRESS.md` |
