**Причина класса:** новая логика страницы (кнопка с двумя нажатиями, состояния ошибок) в шести дизайнах, но по образцу существующих блоков

## Что должно заработать

Блок кнопок для ожиданий `briefing`, `spec`, `plan`, `accept` рисуется во всех шести дизайнах одним кодом; кнопка шлёт запрос по контракту `POST /.ap-act` из `interfaces.md` («Контракт `POST /.ap-act`», «Страница»). Сервер строит таск 03 — страница сверяется только с контрактом (в тестах сервер подменяется заглушкой `fetch`). Не коммитить. В `CHANGELOG.md` ничего не править.

## Из брифа, дословно

> «Кнопками закрываются только ожидания из «Нужно от вас»: ответить на вопрос брифинга и ручной гейт спецификации, принять план (`ask plan`), принять сдачу. Кнопка называет, что именно произойдёт, и просит подтверждение вторым нажатием; пустого ответа нет.»
> «Действия, которые по правилам проекта требуют слов пользователя, **не** становятся кнопками: возврат упавшего таска (`ticket NN reset --by-user`), `finish --by-user`, подтверждение Opus (`opus approve`), снятие требования (`dropped`), любые действия над подписями и ключом. Вместо кнопки страница показывает готовую команду с местом для цитаты и кнопкой «скопировать».»
> «Блок «Нужно от вас» с кнопками рисуется во всех шести дизайнах одним и тем же кодом, дизайны меняют только вид.»
> «Открыто через `file://` или без токена кнопок нет: страница только читает и одной строкой говорит, где взять адрес (`ap.py url`). Сервер остановлен или ответил ошибкой — кнопка возвращается в исходное состояние с понятной строкой, без падения.»
> «Готово, когда: тест на отсутствие токена, на ошибку сервера, на отсутствие кнопок при пустом `waiting`.»

## Разделы спецификации

«Решение» (R34, R34.1, R35, R35.1), «Тесты, которые обязаны быть» — блок «Страница»; в `interfaces.md` — контракт и «Страница».

## Критерии приёмки

- [ ] При `waiting.kind` из `briefing|spec|plan|accept`, адресе `http(s)` с токеном в `location.search` блок кнопок рисуется (у `briefing` — поле ответа, пустое не отправляется); подпись называет действие; первый клик меняет подпись на «Точно? нажми ещё раз», запрос уходит только по второму клику: POST на `/.ap-act` + `location.search` с телом из контракта
- [ ] Без токена или на `file://` кнопок нет, есть одна строка про `ap.py url`; при пустом `waiting` и при видах `action`/`stop` блока кнопок нет
- [ ] Ответ не 200 (в том числе 403/409/413/503) или отказ `fetch` (сервер остановлен) — кнопка возвращается в исходное состояние с понятной строкой, страница не падает; 200 — кнопка заменяется строкой «Ответ отправлен»
- [ ] Блок команд со словами пользователя (`ticket NN reset --by-user "<цитата>"`, `finish --by-user "<цитата>"`, `opus approve --by-user "<цитата>"`, пометка `dropped` в `manifest.md`) показывается с кнопкой «скопировать» и без кнопки действия, когда страница открыта по адресу с токеном и есть упавший таск или ожидание `action`/`stop`
- [ ] Блок рисуется одним кодом во всех шести дизайнах (тест по `DESIGN_IDS`), контраст, 44 px и отсутствие внешних запросов не нарушены, шаблон не больше потолка (`TEMPLATE_CEILING`), прежние тесты шаблона зелёные; полная проверка `python tools/run-tests.py` зелёная
