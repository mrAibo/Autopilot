# 03 — Старый сервер перезапускается, ping с nonce, чистый `serve.log`

**Требования:** R03, R09
**Зависит от:** 02
**Зона:** `skills/autopilot/tools/ap.py` · `tests/test_followups_token.py` · `tests/test_ap_audit.py` · `tests/test_dashboard_actions.py` · `docs/adr/0013-server-ping.md`
**Волна:** 2
**Ревью:** нет
**Модель:** обычная
**Класс:** сложный
**Риск:** обычный
**Причина класса:** меняет протокол проверки «свой сервер» и поведение перезапуска, где легко получить петлю перезапусков или чужой сервер

## Что должно заработать

Сервер, поднятый старым `ap.py` (без `POST /.ap-act`), перестаёт жить до `finish`: следующая команда `ap.py` его перезапускает. `/.ap-ping` отвечает на nonce клиента, поэтому записанный ответ нельзя переиграть. Управляющие символы в запросе не подделывают строки в `serve.log`.

## Из брифа, дословно

> «Сервер, запущенный старым `ap.py`, отвечает 501 на POST до перезапуска (`finish` или новый `init`)»
> «Сервер: управляющие символы подделывают `serve.log`; `/.ap-ping` без nonce»

## Разделы спецификации

Решение R03 + R09; `interfaces.md` — «Сервер (T03)»; `notes.md` — «Сервер».

## Критерии приёмки

- [ ] `server_is_ours` шлёт случайный nonce и принимает только `hmac(serve.token, "autopilot-ping|<port>|<nonce>")`; ответ без nonce, 404 и устаревший ответ не сходятся (тесты на каждый случай)
- [ ] Сервер без nonce-ответа (имитация старого: отдаёт 404 на `/.ap-ping`) при следующей команде `ap.py` убивается и поднимается заново; свежий сервер новой версии не перезапускается второй раз подряд (нет петли)
- [ ] Строка запроса с управляющими символами (`%0d%0a`, сырой `\r`, `\x1b`) попадает в `serve.log` с `?` вместо них; подделанной второй строки нет
- [ ] ADR `0013` дополнен: nonce, перезапуск старого сервера, отвергнутое «версия в pid-файле» одной строкой почему; `docs/adr/0015` не правится
- [ ] `tests/test_followups_token.py:299` (старое правило «404 = свой по командной строке») обновлён под новое правило; весь файл и `test_ap_audit.py`, `test_dashboard_actions.py` зелёные
