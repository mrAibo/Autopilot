Текст профиля не содержит пути к таску: таск называет запрос.

### Волна 5 — скорость инструментов

**R14. `ap.py` на Windows не зовёт PowerShell на каждую команду**
- Корень: `serve()` в `ap.py` при живом сервере вызывает `is_guarded_server(cmdline(pid))`, а `cmdline` на Windows — это `Get-CimInstance` через PowerShell, 0,56 с на каждую команду, меняющую состояние.
- Живой сервер подтверждает себя по HTTP: ответом, который может дать только сервер этого прогона (производное от `serve.token`, сам токен не передаётся). Проверка процесса остаётся для случая, когда такого ответа нет.
- Защита из `docs/adr/0001` не ослабляется: проверки Host, Origin, `Sec-Fetch-Site` и токена прежние.
- Тест: при здоровом сервере команда не запускает PowerShell (подмена `_ps`); чужой процесс на том же порту не признаётся своим.

**R15. История прошлых сборок не перечитывается каждой командой**
- Корень: `compute_history` в `ap.py` читает `state.js` каждой архивной сборки на каждую команду (известный баг; архивов уже 11).
- Сводка по архиву кэшируется по времени изменения и размеру файла в игнорируемом git файле внутри `.autopilot/`. Битый или отсутствующий кэш пересчитывается молча.
- Тесты: второй вызов не открывает архивы; изменённый архив пересчитан.

**R16. Аттестации не растут без конца**
- На `finish` строки `attestations.jsonl` этого прогона переносятся в папку прогона; общий файл начинается заново. При незавершённом прогоне файл не трогается.
- Проверки `attestFrom` и подписи работают как раньше. Тесты: перенос на `finish`; повторный `finish` после `reopen`.

**R17. Тесты самого Autopilot идут параллельно**
- Замер 2026-11-16, Windows, Python 3.14, один процесс: 959 тестов за 532 с, все зелёные, 5 пропущено. Тридцать самых медленных вместе дают около 150 с (самый долгий 17 с); остальное — длинный хвост тестов по 3 с в `test_ap.Run`, каждый из которых несколько раз запускает `ap.py` отдельным процессом. Делить есть что: одного медленного теста, который задаёт нижнюю границу, нет.
- Сначала выяснить, сколько из этих 3 с уходит на проверку сервера и PowerShell (R14) и не хватает ли тестам `--no-serve`: если дело в этом, часть выигрыша приходит без параллельности. Результат — одна строка в отчёте.
- `tools/` получает запускатель на стандартной библиотеке, который делит файлы тестов между процессами и печатает общий итог в том же формате (всего, упало, пропущено). Обычная команда `python3 -m unittest discover -s tests` остаётся рабочей и остаётся командой CI, пока параллельный прогон не показал те же числа три раза подряд.
- Тесты, которым нужен общий ресурс (порт, домашняя папка), помечены и идут последовательно.
- В `AGENTS.md` записано фактическое время до и после.

### Волна 6 — удобство

**R18. Профили агентов сданной сборки удаляются**
- `ap.py finish` удаляет из `.claude/agents/` профили своего прогона: те, что записаны в его `state.js` (`routing.agentType` тасков, `roleAgents`, `repairAgent`, `opusAgents`). Постоянные профили из R01, чужие файлы и профили другого незавершённого прогона не трогаются.
- `ap.py agents prune` удаляет профили `autopilot-*` с именем прогона, на которые не ссылается ни один незавершённый прогон; без `--apply` только печатает список.
- `reopen` сданной сборки: путь к профилям прежний (`plan-models --apply` и новый чат) — одна строка в `phases/0-preflight.md`.
- Сбой удаления не срывает `finish`. Тесты: свои удалены, чужие и постоянные остались; `prune` без `--apply` ничего не удаляет.

**R19. Прогноз после плана и расход в отчёте**
- Экран плана получает одну строку: сколько тасков и оценка токенов и минут, из R11 по тем же классам. Истории нет — строки нет; оценка названа оценкой.
- Итоговый отчёт (`phases/8-final.md` §3) получает строку «Расход и время»: токены оркестратора и субагентов, минуты работы, из `state.js` → `spend`. Деньги не называются: цен в журнале нет.
- Если пользователь назвал лимит токенов, он виден на дашборде рядом с расходом (`budgetTokens` уже есть в `state.js`); вступительный блок называет эту возможность одной строкой.
