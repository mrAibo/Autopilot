**Причина класса:** подтверждение сервера по hmac от токена затрагивает защиту токена из ADR 0001; плюс общая серверная часть и поведение страницы при 403

## Что должно заработать

`ap.py` не зовёт PowerShell на каждую команду при живом сервере; удалённый `serve.token` не оставляет 403 до перезапуска; страница с неверным токеном показывает подсказку и не опрашивает вечно.

## Из брифа, дословно

> **R14. `ap.py` на Windows не зовёт PowerShell на каждую команду**
> - Корень: `serve()` в `ap.py` при живом сервере вызывает `is_guarded_server(cmdline(pid))`, а `cmdline` на Windows — это `Get-CimInstance` через PowerShell, 0,56 с на каждую команду, меняющую состояние.
> - Живой сервер подтверждает себя по HTTP: ответом, который может дать только сервер этого прогона (производное от `serve.token`, сам токен не передаётся). Проверка процесса остаётся для случая, когда такого ответа нет.
> - Защита из `docs/adr/0001` не ослабляется: проверки Host, Origin, `Sec-Fetch-Site` и токена прежние.
> - Тест: при здоровом сервере команда не запускает PowerShell (подмена `_ps`); чужой процесс на том же порту не признаётся своим.

> **R20. Понятные ошибки дашборда**
> - Неверный или отсутствующий `?t=`: страница один раз показывает подсказку про `ap.py url` и перестаёт опрашивать сервер. Удалённый `serve.token`: следующая команда `ap.py` поднимает сервер заново, а не оставляет 403 до перезапуска. Оба — известные баги из `PROGRESS.md`.
> - Тесты на оба случая.

## Критерии приёмки

- [ ] Сервер отдаёт путь `/.ap-ping` (вне `OPEN_PAGES`, без `?t=`), ответ — hex hmac-sha256 от токена и порта (`ap.ping_digest`); токен по сети не уходит; проверки Host, Origin, `Sec-Fetch-Site` и токена остальных путей прежние
- [ ] `ap.server_is_ours(port)` сверяет ответ через `hmac.compare_digest`; `serve()` и `ap.py url` при совпадении не зовут `cmdline`/`_ps`; при отсутствии ответа — прежний путь (`is_guarded_server(cmdline(pid))`) и перезапуск; чужой процесс на порту своим не признаётся
- [ ] Тест: при здоровом сервере `_ps` и `_run` не вызываются (подмена с `AssertionError`); чужой http-сервер на порту без ping не признан; удалённый `serve.token` → следующий вызов `serve()` перезапускает сервер (патч `subprocess.Popen`); два теста `test_followups_token.py`, патчащие `http_ok`/`is_guarded_server`/`cmdline`, патчат и новую функцию, иначе поднимется настоящий сервер на порту 8123
- [ ] Страница: при `?t=` в адресе, когда `state.js` не загрузился или пришёл `STATE=null` (неверный токен), по http один раз показывает `tokenHint()` и перестаёт опрашивать (после 2 промахов подряд без загруженного `STATE`); «сервер умер» (`lost`) остаётся отдельным сообщением; кнопка «обновить» возобновляет; тест node-vm (расширить `HARNESS`: `location.protocol` `http:`, `search`, `setTimeout`-стабы, вызов `onerror` у созданного скрипта)
- [ ] ADR `docs/adr/0013-…` (формат «Контекст / Решение / Почему / Последствия») и пункт «Последствия» в ADR 0001; `AGENTS.md` не править (пункт про сервер обновит оркестратор)
- [ ] Известный баг `kill_orphans`→`processes()` через PowerShell на каждую команду после `finish`: не чинить, назвать в возврате
- [ ] `.autopilot/dashboard.html` и `.autopilot/*.py` не править
