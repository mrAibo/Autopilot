## Контекст
Влитие таска сейчас встаёт на красной проверке соседа: чужой таск в работе правит те же файлы или цель ушла вперёд, и это видно только в конце (R25b). R25a требует до слияния посчитать уход цели от `baseCommit`, чужие коммиты в зоне таска и соседние таски с пересекающимися файлами. Влитие идёт cherry-pick одного коммита в рабочей копии (`worktrees.land`). `ticket NN start` пишет `tk["startHead"]` — HEAD на момент старта таска.

## Решение
- `land_check.preflight(root, start_head, base_commit, zone, ticket, active_zones)` не меняет репозиторий. Считает уход от `baseCommit` (`git rev-list --count`), файлы зоны, которые правили чужие коммиты после `startHead` (`git diff --name-only`), и пересечения с зонами других тасков в работе.
- Пересечение считается по путям файлов, а не по слиянию.
- Коммиты тасков этой же сборки до `startHead` пересечением не считаются.
- Конфликт или пересечение — отказ с командой «что делать»: «дождись», `ticket NN land --zone …` или «реши с пользователем». Код выхода 2.
- Проект в подпапке репозитория: `unsupported` → предупреждение, отказа нет.
- `worktrees.land` вызывает ту же проверку до cherry-pick.
- `--allow` не меняется (ADR 0026 касается `--include`).

## Почему
- Отвергнуто: `git merge-tree`. Он считает слияние двух веток, а здесь влитие — cherry-pick в рабочей копии. Нужный вопрос — какие файлы трогали чужие коммиты и таски, а не сольётся ли.
- Отвергнуто: запускать проверки соседа, чтобы заранее увидеть красное. Это и есть известная проблема: посадка встаёт на чужом красном.
- Отвергнуто: отсчёт от `baseCommit` для пересечений. Коммиты тасков этой же сборки до старта дали бы ложные пересечения, поэтому нужен `startHead`.
- Цена: ложные отказы, когда два таска правят один файл в одной зоне. Выход — `--zone` без общих путей или слово пользователя.

## Последствия
- Проверка не сливает и не пишет в репозиторий; её можно гонять повторно.
- Новое поле `tk["startHead"]` необязательно. Для старого таска без него поведение проверки в записи не закреплено; это надо проверить по коду и тестом.
- Проект в подпапке репозитория остаётся без проверки, с предупреждением.
