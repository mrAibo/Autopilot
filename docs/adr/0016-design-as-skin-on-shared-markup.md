# 0016. Дизайн дашборда — скин на общей разметке

## Контекст
Пользователь хочет выбирать один из шести дизайнов на живых данных боевого дашборда. В галерее `mockups/dashboard-2026/` у каждого дизайна своя разметка и зашитые данные.

## Решение
Дизайн включается атрибутом `<html data-design="<id>">` и меняет токены и оформление тех же блоков. Реестр `DESIGNS` задаёт id, номер, имена, подпись, акцент, теги и схему. Токены лежат только в блоках `html[data-design="<id>"]`, общая разметка имён дизайнов не знает. Особые элементы (тикер, шкалы, размерные линии, штамп, кольцо) — слоты: функции от `window.STATE` возвращают `''` без данных, CSS показывает слот только своему дизайну. Всё остаётся в одном файле `dashboard-template.html`.

## Почему
- Iframe-витрина с вшитым снимком данных отвергнута: в iframe данные зашиты, а пользователю нужны живые; к тому же это шесть страниц, которые расходятся с боевой.
- Отдельная разметка на каждый дизайн отвергнута: каждое изменение блока пришлось бы делать шесть раз, и набор секций и якорей разошёлся бы между дизайнами. Теперь это проверяется одним тестом по шести дизайнам.
- Общий слой слотов вместо отдельной разметки: особые элементы нужны одному-двум дизайнам, а данные у них общие. Отдельная разметка продублировала бы чтение состояния.
- Несколько файлов отвергнуты: `dashboard_upgrade.py` и копирование в проект работают с одним файлом, смена формата сломала бы установленные дашборды.

## Последствия
- Седьмой дизайн — запись в реестре и блок токенов, он обязан задать все общие токены.
- Дизайн ограничен общей разметкой. Чертёж и Терминал могут выйти беднее макетов; расхождения записываются в `dashboard-views.md`.
- Один файл растёт: потолок 450 КБ в тесте, при нехватке места режется дизайн, а не потолок.
- Старый базовый `:root` остаётся запасным слоем для неизвестного `data-design`.
