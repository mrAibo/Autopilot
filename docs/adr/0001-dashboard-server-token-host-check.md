## Контекст
Сервер дашборда отдавал весь `.autopilot` без проверки `Host`/`Origin` и без токена. `state.js` — обычный скрипт `window.STATE = {...}`, поэтому любая чужая страница могла прочитать состояние сборки (R02, A02).

## Решение
Сервер отвечает 403, если `Host` не `127.0.0.1:<порт>` и не `localhost:<порт>`, если заголовок `Sec-Fetch-Site: cross-site`, или если к `state.js` и другим данным прогона нет `?t=<токен>`. Сама страница и статика токена не требуют. Токен случайный и хранится в файле `.autopilot/serve.token`, который игнорируется через `serve.*` в `.gitignore`. Адрес, который печатает `ap.py`, содержит `?t=`. Открытие через `file://` токена не требует, потому что данные уже внутри снимка.

## Почему
- Токен аргументом командной строки отвергнут: он пропадает при перезапуске `ap.py`, а дашборд перезапускается вместе со сборкой. Поэтому токен — файл.
- Одной проверки `Host`/`Origin` недостаточно: заголовки подделываются любым локальным клиентом, который не является браузером. Токен — отдельный секрет, который проверка заголовков не заменяет.

## Последствия
- Токен живёт в файле, пока его не удалят. Любой, кто получил адрес с `?t=`, читает данные прогона на этой машине, поэтому адрес с токеном не стоит вставлять в чат или скриншоты.
- Закладка на адрес без `?t=` перестаёт работать (403). Открытые вкладки нужно перезагрузить по новому адресу.
- Проверка `Host` привязана к порту: при смене порта адрес нужно перепечатать.
- Снимок через `file://` без токена отдаёт те же данные без защиты. Это принятое исключение: кто копирует папку, копирует данные.
- Коды ответов проверены тестами. Поведение в реальном браузере не проверено.
- Путь `/.ap-ping` (ADR 0013) открыт без `?t=`, но под теми же проверками `Host`, `Origin` и `Sec-Fetch-Site`; он отдаёт hmac от токена и порта, не сам токен. Удалённый или переписанный `serve.token` перезапускает сервер, а не оставляет 403. Страница с неверным или отсутствующим `?t=` один раз показывает подсказку про `ap.py url` и перестаёт опрашивать сервер.
