# 0028. Закрытие оставшихся известных багов: plan-fact, land_check, blocker confirm, redproof

Статус: принято (2026-11-20).

## Контекст

В «Известных багах» `.autopilot/PROGRESS.md` после ADR 0027 остались четыре дефекта: «сделано» в `plan-fact record` принималось по одному существованию пути, а `record` стирал все строки «план: …» в `concerns`, включая ручные; `land_check` не узнавал свой коммит без префикса темы и не видел правки, пришедшие через merge-коммит (`git show --name-only` у merge пуст); ошибочный `confirmed` у `blocker confirm` исправить было нельзя; `redproof` принимал `ImportError` на ненаписанную функцию как красный тест.

## Решение

- `plan_items._proved`: `путь:N` — файл есть, `1 <= N <=` число строк; `путь::имя` — имя встречается в тексте файла (utf-8, `errors=replace`); хоть одно доказательство годится.
- `cmd_plan_fact` удаляет из `concerns` только точные строки `план: <id> — <статус> — <текст>` по прежним не-«сделано» пунктам `planFact.items`; прочие строки с префиксом остаются.
- `ticket NN land` пишет трейлер `Autopilot-Ticket: NN`; `land_check._own` признаёт свой коммит по префиксу темы или по этому трейлеру. Для коммита с двумя и более родителями файлы берутся как `git diff --name-only -z --relative <sha>^1 <sha>`.
- `blocker confirm ... --verdict not-confirmed --quote "…" --by-user "<слова пользователя>"` поверх `confirmed` у открытого блокера: статус `downgraded`, условие в `concerns`, прежний вердикт в `secondPass.replaces`, цитата пользователя в `secondPass.byUser`, событие `corrected`. Без `--by-user` — отказ с командой; повтор `confirmed` и прочие сочетания — отказ, как раньше (ADR 0027).
- `redproof` отказывает и на `ImportError`, `ModuleNotFoundError` (строка исключения в начале строки вывода) и `cannot import name`; `phases/kind-bug.md` согласован: сперва заглушка, затем красный тест на `AssertionError`.

## Последствия

- Доказательство «сделано» строже: ссылка на строку за концом файла или на отсутствующее имя понижает пункт до «не сделано».
- Прежние коммиты без трейлера признаются своими только по префиксу темы, как раньше.
- Поправка `confirmed` требует слов пользователя; оркестратор сам её сделать не может. Поправка `not-confirmed` -> `confirmed` не предусмотрена.
- Осознанно не решено: `::имя` ищется подстрокой в тексте (комментарий или строка тоже сойдут); `ImportError` внутри самого теста на реальную ошибку импорта (баг в самом импорте) красным не считается.
