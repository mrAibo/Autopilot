## Контекст
Ключ подписи гейтов лежал открытым файлом `~/.autopilot/gate.key`. Доступ субагента к этому ключу через Bash хуком не закрывался; ограничение было задокументировано в `docs/autopilot/claude-code.md:55` (R29, I17).

## Решение
На Windows ключ защищён DPAPI через `ctypes` (`CryptProtectData`). В `gate.key` лежит блок с префиксом `dpapi:`. Старый незащищённый `gate.key` читается и переписывается уже защищённым. Если DPAPI недоступен или вызов падает, работает прежнее поведение (файл), и выводится одна строка предупреждения. На macOS и Linux ключ остаётся файлом `gate.key`. Новых зависимостей нет.

## Почему
- Оставить файл отвергнуто: это ограничение, которое I17 просит сузить. Подписи без защиты ключа не закрывают подделку.
- Внешняя библиотека (`keyring`, `pywin32`) отвергнута: проект работает только на стандартной библиотеке Python (AGENTS.md). `ctypes` вызывает DPAPI без зависимостей, это единственный такой способ (spec).
- Хранилище ОС на macOS и Linux отвергнуто для этой сборки: пользователь решил («ok»), там остаётся файл.

## Последствия
- Ключ привязан к учётной записи Windows. Проект, скопированный на другой компьютер или под другого пользователя, не проверит старые гейты. Потеря профиля Windows означает потерю ключа.
- Ветка DPAPI работает только на Windows и в этой среде не проверена. На других ОС её тесты пропускаются. Проверка — через Windows-часть CI (Ubuntu и Windows, AGENTS.md) и вручную.
- В `gate.key` теперь два формата: старый файл и блок `dpapi:`. Читатель должен понимать оба. Старые версии навыка не прочитают блок `dpapi:` — это предположение, не проверено.
- На macOS и Linux защита слабее, чем на Windows. Это принятое решение, а не пробел.
- Если вызов `ctypes` падает, навык молча (с одной строкой предупреждения) откатывается к файлу. Защита может тихо не работать, и заметить это можно только по предупреждению.
