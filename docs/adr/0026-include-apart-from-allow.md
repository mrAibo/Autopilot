## Контекст
`ticket NN land` пропускает только файлы зоны таска. Чужой новый файл (например `docs/adr/*`) нужно разрешить `--allow`, но тогда он в коммит таска не попадает (G01). `--allow` по-прежнему означает «файлы, грязные до таска» и не меняется (R25c). Нужен способ явно положить чужой файл в коммит таска.

## Решение
- `ap.py ticket NN land --include a,b` разрешает и коммитит файлы вне зоны, новые и изменённые. Коммит идёт через `commit_paths`.
- `--allow` остаётся как был: разрешает, но в коммит не кладёт.
- Без `--include` чужой файл даёт прежний отказ с подсказкой про `--include`.

## Почему
- Отвергнуто: сделать `--allow` коммитящим. Меняется смысл опции, которую пользователь уже знает, и R25c этого запрещает.
- Отвергнуто: коммитить `docs/adr/*` автоматически. Чужой файл попал бы в коммит без явного решения; список в команде делает решение видимым.
- Отвергнуто: расширять `--zone`. Зона задаёт владение таском, по ней же считаются пересечения (ADR 0025); её расширение сделало бы чужой файл своим.
- Цена: каждый файл надо перечислить явно.

## Последствия
- Два флага с разным смыслом: `--allow` — разрешить без коммита, `--include` — разрешить и закоммитить. Подсказки и документация должны различать их.
- `--include` не меняет `--allow` и не снимает отказы цитатой `--by-user`.
- Как `--include` сочетается с проверкой перед влитием (ADR 0025), в записи не закреплено; это надо проверить тестом.
