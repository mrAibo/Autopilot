# 0017. Одна страница в раскладке A «Лента» вместо девяти раскладок

## Контекст
В шаблоне было девять раскладок с вкладками и выбор вида в combobox; выбор дизайна добавлял вторую ось. Пользователь решил 2026-11-19: основа — раскладка A «Лента».

## Решение
`page(c)` — единственная раскладка: колонка до ~1100 px, шапка, герой, закреплённая полоса «ждёт ответа», секции `<details class="sec">` по важности. Из шаблона убраны `VIEWS`, `VIEW_IDS`, `VIEW_HOME`, вкладки, лента `.views`. До 520 px страница сжимается в один столбец по правилу адаптивности. Ключи `autopilot-view` и `autopilot-boardmode` и атрибут `data-view` читаются без ошибки и игнорируются; доски таска и требований показаны обе, переключателя нет. Прежняя договорённость «"Классика" держит старые цвета, "Сейчас" по умолчанию» отменена: по умолчанию дизайн `aurora`, старые цвета остались запасным слоем.

## Почему
- Девять раскладок × шесть дизайнов отвергнуты: по брифу «при слиянии раскладки проще проверить шесть дизайнов, чем девять × шесть».
- Раскладки B «Пульт» и C «Конвейер» в сборку не входят: выбрана A (решение пользователя 2026-11-19); по брифу одна колонка одинаково красится шестью дизайнами и работает на всех ширинах.
- Оставить «Классику» отдельным видом отвергнуто: это раскладка, а девять прежних раскладок уходят целиком (бриф, R30).
- Вкладки заменены секциями `<details>`: так требует бриф; причины сверх брифа в спецификации не записаны.

## Последствия
- Прежние пользователи теряют выбранный вид без сообщения; страница не ломается, ключи в `localStorage` остаются мёртвыми.
- Переписаны тесты `test_dashboard_views`, `now`, `boards`, `details` под одну страницу.
- Мёртвый CSS `.nowh`, `.ov3`, `.tl2` и атрибут `data-narrow` остались: их читают `test_dashboard_now.py` и `test_dashboard_boards.py` (см. 0019). Это долг, а не решение.
- Рейка строится по якорям `#mission #tasks #models #quality`, подсветки «текущего вида» нет.
