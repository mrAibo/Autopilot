## Контекст
`ap.py` не коммитил: коммит делал оркестратор командами из фазы. Замер первого таска дал в среднем 8,2 шага главной сессии на посадку таска, медиана 3.

## Решение
Один помощник `commit_paths(paths, message, trailers)` выполняет `git commit --only -- <пути>` с трейлерами прогона. Его вызывают `chore <имя>` и `ticket NN land`. Ни одна из команд не делает `git add -A` по дереву и не использует `git stash`.

## Почему
- Отвергнуто: оставить коммит оркестратору по тексту фазы. Это шаги, которые замер назвал причиной длинной посадки; без переноса R05 не сокращается.
- Отвергнуто: отдельный код коммита для каждой команды. Одна точка записи даёт одну проверку правила `--only` и один набор тестов.
- Отвергнуто: `git add -A` и `git stash` в помощнике. Оба запрещены правилом проекта; `--only` коммитит только названные пути и не трогает файлы, грязные до запуска.

## Последствия
- `ap.py` впервые пишет в git. Неверный список путей попадёт в коммит; защита — проверка `git status` до и после и зоны.
- Помощник проверяет состояние дерева и список путей, но не содержимое. Ошибка в самом коде попадает в коммит так же, как и раньше.
- Строгий изолированный прогон коммитит по-прежнему через `worktree`; `land` там отказывает, поэтому путей коммита два.
- Список путей берётся из зоны таска и объявления команды; ошибка в объявлении видна только по проверке дерева.
