# Phase 5 — Claude Code host (digest)

Working digest of `phases/5-host-claude.md`. **Read the full text only if something below is not enough** (hook install commands, the strict-run fork/isolation rules, the `?` line from `init`).

- Call only routed `autopilot-…` agents; the guard denies any other Agent name, `Agent(fork)` and Claude's own `isolation`. Never `/subtask` or `/fork` in strict tickets. Claude Code sees only agents that existed at session start; hooks and profiles are installed in Phase 4 (idempotent).
- **Ordinary run (no `--strict-routing`)** — four permanent profiles in `.claude/agents/`, no `model`/`effort` inside: executor (tickets, fix tickets `F<n>`, memory and ADR agents) `autopilot-executor` · point/branch review and the G2 coverage check `autopilot-reviewer` · blind acceptance `autopilot-acceptance` · explorer (notes, context pack, commit log) `autopilot-explorer`. **Always pass `model` and `effort` in the call**, from `plan-models` or the router; for `F<n>`: `ap.py ticket F1 route --model <name> --effort <level> --reason "…"` (Haiku/Sonnet; Opus only after user approval; never Fable). The launch prompt carries the ticket path and limits.
- «Agent type not found» in an ordinary run → `general-purpose` for that role, one line («лёгкие профили видны со следующего чата — дальше будет дешевле»), never a stop. A `?` line from `init` is asked once: may the profiles also live in user settings → `ap.py agents install-user --by-user "<его слова>"` or `--decline`; no words, nothing written outside the project.
- **Strict run roles** (`state.js` → `roleAgents`): point review and repair re-review → `roleAgents.reviewer.agentType`; whole-branch review → the name printed by `ap.py agent-for reviewer --diff-lines N` (N from `git diff --shortstat <baseCommit>..HEAD`; Opus reviewer only if the user approved the role and N > 3000); blind acceptance → `roleAgents.acceptance.agentType`; coverage reader, memory and ADR agents → `roleAgents.explorer.agentType` (read-only; you write the files verbatim). Never an executor profile for another role.
- **Fix tickets `F<n>`:** no profile of their own; `ap.py ticket F1 route --provider anthropic --reason "…" --capabilities .autopilot/model-capabilities.json` assigns `repairAgent` (or the Opus repair profile if the user approved `repair`; `ap.py agent-for repair` prints the name). One fix ticket at a time.
- Strict: «Agent type not found» → never fall back: `ap.py ticket NN reset`, `ap.py ask stop`, the new-chat message from `4-plan.md`. `ticket NN done` needs the attestation (`resolvedModel`). Desktop Agent calls run async; this does not block the gate.
