# Phase 8 — Acceptance (digest)

Working digest of `phases/8-final.md`. **Read the full text only if something below is not enough** — and always read the full text for **the blind checker's prompt (round 1 and round 2) verbatim**, the report template, and the progress-file template: they are written out there and must be copied, not paraphrased.

`ap.py stage final`. Three isolated subagents, one question each. Blind checker and ADR agent go out **in one message**; the memory agent after the checker returns (it needs the commands the checker proved). Each gets a routing brief / ready router verdict, `model`+`effort` in the call (ordinary run: blind checker `autopilot-acceptance`; memory and ADR agents `autopilot-executor`; strict: `roleAgents`). Never inherit Astra/Fable.

| Agent | Receives | Never receives |
|---|---|---|
| blind checker | every `*-brief.md` oldest first, whole, `## Дополнения` included; the repository | `spec.md`, `manifest.md`, tickets, `planFact` |
| ADR *(T2+)* | `spec.md`, `manifest.md`, `interfaces.md`, `notes.md` | the repo |
| memory | the repo, the memory file, `interfaces.md`, the tier, the commands the checker ran | `spec.md`, tickets |

**G4 — blind acceptance.** The prohibition is in the prompt: don't open `.autopilot/`, no skills, no agents, send nothing outside; **clone the repo into a temp folder** and install from scratch; run the project and walk the main scenario (does not start = first finding; cannot run at all = say what stopped it); per requirement реализовано / частично / нет + one line; formal-but-useless = «частично»; return the exact commands that started it and their results; no code-quality opinions. Compare with the manifest: `done`+частично/нет = 🔴 drift (a ticket or a report line, never your edit); `placeholder`+частично and `dropped`/`deferred`+нет are expected; built but not in the brief → reported. **At most two rounds** (`BLIND_ROUNDS = 2`, `ap.py` refuses a third): 🔴 → one round of fixes (`F2`) → one re-check by a **fresh** checker with the new-clone prompt and the list of round-1 mismatches **in the brief's words** (not ids) → report; what is still 🔴 goes to «Открытые вопросы». Record: `ap.py blind checked=N matched=M --mismatch "…"` (round 2: `K` = listed requirements + 1; merged by `ap.py`; refuses K above round-1 mismatches + 1). Hiding a drift is the failure; a build nobody launched goes to «Что нужно от тебя». Screenshots only with `AUTOPILOT_BLIND_SHOTS=1` (`shots.py`, folder outside the clone, never the dashboard/spec).

**Memory and ADRs:** read `phases/9-memory.md` before spawning (Moments 3 and 4 are their brief). User's own memory file → `memory-proposal.md`, not written into.

**Report:** first `ap.py tests N/M` (full check once more). Write in the user's language, plain, **from files re-read now, not from memory**: Решения, принятые за тебя (`ASSUMPTION`s; first in full) · Готово (the blind verdict, not manifest `done`) + «Запустить» · Что нужно от тебя (`placeholder` + `debt`; mandatory even empty: «всё заполнено») · Что не вошло (always, even one line; `deferred`/`dropped` with quotes) · Что добавил сверх заказанного (`additions` vs spec `A##`) · Что пошло не по плану (`D##`, failed tickets) · Что осталось после ревью (`report`; the line «план: N из M», `phases/8-plan-fact.md`) · Открытые вопросы (`blind`, unbuilt `coverage` items, `landedWith.problems`) · Opus section only with `opusApproval` (`ap.py opus status`, `measure-run.py`) · Расход и время (`spend`, stage minutes; no money) · Память проекта (user's file → one question) · Где что лежит. Secrets by name only; no diffs, code file names or test names; don't prettify.

**Progress file** `.autopilot/PROGRESS.md`, rewritten whole at every landing from re-read files (<60 lines, empty section «—»): Договорились (`dropped` + quotes, lasting preferences, confirmed assumptions, still-true `carried.md`; not what an ADR holds) · Не доделано · Известные баги · Правки без автопилота. Opus line: «Opus — по подтверждению пользователя: …» or off.

**Landing:** `finish` refuses open `blockingFindings`, un-reconciled `repairFindings`, resolved fixes whose commits left history; resolve via `ap.py blocker resolve --id BNN --commit SHA --tests N/0 --note "…"` only with a real commit, green tests and independent review. Stale/missing G3 → `ap.py check-plan`, redo G1/G2/G4 if the plan changed; `F<n>` alone don't make it stale. **manual only:** show the report, `ap.py ask accept --note "принять сдачу"`, `ap.py await` (code 0 lands; 3 → ask once in chat; the button is not words for `--by-user`). Order: (1) memory file/proposal, ADRs, glossary, progress file written; (2) `python3 .autopilot/ap.py finish --result "<one line>"` — if it lists waivable problems (gate not passed, ticket not `done`, no commit, no green full run, open rows), show them and ask; **only the user's words** allow `finish --result "…" --by-user "<цитата>"` (never on your own; manifest rows stay as they are, `dropped` only the user); (3) final commit: `git add -A -- .autopilot AGENTS.md CLAUDE.md docs/architecture.md docs/adr CONTEXT.md GLOSSARY.md .env.example .gitignore && git commit -qm "Autopilot: сборка сдана" --trailer "Autopilot-Run: <папка>" -- <same paths>` (omit missing paths and the user's memory file; **subject exactly «Autopilot: сборка сдана»**; a changed file outside what any ticket owned → «осталось незакоммиченным»); (4) the report. Say nothing about the dashboard freeze.
