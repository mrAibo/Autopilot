# Phase 4 — Plan (digest)

Working digest of `phases/4-plan.md`. **Read the full text only if something below is not enough** (the ticket-file template, the wide-change recipe, the routing score details, the `plan-models` flags, the exact cost-hint wording).

`ap.py stage plan`. Cut the spec into tickets, one subagent per ticket in a fresh context. Every ticket boundary is a cold start (60–100K tokens): fewer, denser tickets beat thin ones.

**Size** (from the volume of code, not the length of the spec; ~3,000 changed lines per executor): ≤3K → **one ticket, T0** (no waves, no point review; default for a list of edits in existing code) · 3–6K → 2, T1 · 6–18K → 3–6, T2 · 18–36K → 7–12, T3 · more → not allowed, split into two runs. State volume, tier and count in one line; `ap.py set tier=T2`.

**Cutting:** each ticket is a narrow but complete path through every layer (data, logic, interface, tests). Shell/schema/shared primitives = ticket 01, alone. Tickets closing `R` before tickets closing only `A`. Merge pass before any file is written: merge neighbours that stay under ~3K lines, tickets on the same files, thin tickets with a natural parent (under three criteria + same files as a neighbour = a checklist item); split only past ~3K lines or a long debugging loop. A **wide change** (shared thing used by many zones) = expand → migrate (one ticket per zone) → contract; only when it crosses more zones than one ticket owns.

**Waves and zones:** `wave = 1 + max(wave of dependencies)`, then split by zone — two tickets writing the same files never share a wave. Every ticket names its zone (tests included). A written wave number is never renumbered.

**Review per ticket:** `да — фундамент` (ticket 01 others build on; expand step), `да — <риск>` (own code is sign-in/passwords/sessions, keys, money, deleting/migrating user data), else `нет`; T0's one ticket is `нет`.

**Route is the planner's assessment, written in the ticket header:** `**Класс:** механический|обычный|сложный`, `**Риск:** обычный|высокий`, `**Причина класса:** ≤200 знаков` (`check-plan` refuses without class and reason; the router never searches the text for words; a sensitive zone is a floor; docs-only = risk 0; fix tickets `F<n>` exempt). After `tickets` + `check-plan`: `python3 .autopilot/ap.py plan-models --provider openai|anthropic` (advisory; `--capabilities … --apply` only when the host really supports model+effort, and only against a fresh G3 snapshot). Applied route / unsupported GUI / `--sequential-host` → `4-plan-strict.md`. No Astra/Fable/Opus automatically; no model calls during planning. Haiku ticket (`механический`) only when all four hold: one zone, ≤~150 lines, every criterion is a command with a known result, interfaces already in `interfaces.md`; red → retried once, then `ticket NN retry --cause tests --escalate`. **No ticket only verifies.** After `plan-models`: `ap.py opus propose` (prints only); a non-empty list → `4-plan-opus.md`. No machine paths in tickets/`spec.md` (`tickets` refuses); a changed `done` ticket stops `tickets` with `ticket NN accept-edit --note "…"`.

**Ticket file** `.autopilot/<dir>/tickets/NN-<slug>.md`, header lines kept by name: `Требования`, `Зависит от` (numbers only or `—`), `Зона`, `Волна`, `Ревью`, `Модель`, `Класс`, `Риск`, `Причина класса`; sections «Что должно заработать», «Из брифа, дословно» (the quotes are load-bearing), «Разделы спецификации», «Критерии приёмки» (each checkable and false at the starting commit; no paths/code unless a schema is clearer).

**Before the first ticket:** `interfaces.md` gets the project rules an executor cannot derive — stack and versions; install/run/**one check command**; how to run one test file; what not to touch; a line **`Полная проверка: \`<command>\``** (`ticket land` runs it and counts tests); a ticket's own line **`Целевая проверка: \`<command>\``** makes `land` run that instead — the full check then runs on `stage review` and in `finish` (only if targeted landings happened); a «Команды-генераторы» table `Имя | Команда | Файлы` if a command rewrites files (`ap.py chore <name>`). **Ticket 01 installs every dependency «Решения по реализации» names.**

**Gate G3 and the plan commit:** `ap.py tickets` then `ap.py check-plan` (every live requirement in a ticket and back; zone and wave on each; waves respect dependencies; no zone clash in a wave). Every `!` line is a plan defect. A fresh `check-plan` after ticket/requirement edits invalidates G1/G2/G4 — redo coverage and blind acceptance. `F<n>` tickets are outside this contract. Then the redaction gate over `.autopilot/` and the **plan commit** (the base of every later diff):
`git add -A -- .autopilot .gitignore AGENTS.md CLAUDE.md .env.example && git commit -qm "Autopilot: план сборки" --trailer "Autopilot-Run: <папка>" -- <the same paths> && python3 .autopilot/ap.py set baseCommit="$(git rev-parse --short HEAD)"` — omit missing paths and the user's own memory file; `<папка>` = `dir` without `--wip`. A ticket that exists only in the dialogue is not a ticket.

**Showing the plan:** one line on parallelism only if true («6 тасков в 4 волны»). semi/interview: one screen, a plain line per ticket, «Показываю план и начинаю. Скажи "стоп", если что-то не так», then go; forecast line only if `plan-models` printed one. full: the same as a notification. **manual:** `ap.py ask plan`, explicit «ок» (chat or `ap.py await`) before Phase 5. **Strict Claude Code run:** `4-plan-strict.md` — Phase 4 ends there with a required new chat.

**Handoff (every mode, not strict, not T0), right after the plan screen and before `stage build`:** `python3 .autopilot/ap.py handoff`. Code 3 → say its one line, run nothing else, end the loop (a new chat's `/autopilot` resumes at the build, `0-resume.md`; if its preflight says «the run is going on in another window», answer «продолжает новое окно» — this chat writes nothing more). Code 0 → go on. **Cost hint** (only on a strong model, never at T0, never in a strict Claude Code run), one line after the plan screen in the user's language. manual (offer, answered by the «ок»): «План готов. Дешевле собрать в новом чате на Sonnet в этой же папке — выбери модель, напиши `/autopilot`, сборка продолжится с этого места. Или продолжим здесь.» semi/interview/full (information only, never a new stop): «Дешевле собрать на Sonnet: скажи «стоп», открой новый чат в этой папке на Sonnet и напиши `/autopilot`.» If the user takes it, this chat stays idle — one writer per run. Code 1 → fix what it names, do not stop.
