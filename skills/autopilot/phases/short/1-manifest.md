# Phase 1 — Manifest (digest)

Working digest of `phases/1-manifest.md`. **Read the full text only if something below is not enough** (the secret-pattern table, the brief-file template, the manifest example).

1. **Redaction gate** on every piece of user text before any file/prompt/dashboard: keys (`sk-`, `sk_live_`, `ghp_`, `AKIA`, `AIza`, `xox*`, Telegram bot token, JWT `eyJ`, `scheme://user:pass@host`, `-----BEGIN … PRIVATE KEY-----`, ≥32 hex/base64 next to key/token/secret/password/ключ/токен/пароль). Hit → `[REDACTED:<VAR_NAME>]`, name into `.env.example` empty, one plain line to the user (revoke it, put it into `.env` yourself); **never echo the value**. Run the gate over all of `.autopilot/` before the plan commit.
2. **Brief file** `.autopilot/<dir>/<YYYY-MM-DD>-brief.md`, `ap.py set briefFile=<name>`: the redacted brief **word for word** under «# Изначальная задача», then `## Дополнения`. No paraphrase, no cleanup; everything counts as brief. The text above never changes; everything said later (cancellation, addition, reversal) is appended to `## Дополнения`, dated, verbatim — G2 and G4 read the brief and are forbidden the manifest. A later day → a new dated file. A path instead of words → the file's text is the brief. An audit report → the brief is only the ticked `- [x] **A##**/**I##**` items verbatim + «Вне рамок (не отмечено в аудите): …»; nothing ticked → ask which, never pick.
3. **Atomise** into `manifest.md`: table `ID | Из брифа (дословно) | Статус | Основание | Где`, column order fixed (`ap.py` reads ID col 1, status col 3, appends to «Где»), `|` in a quote → `\|`. One row = one thing true or false on its own; 25–50 rows from a 2000-word brief, under 10 means you summarised. Statuses: `open` · `in-spec` (you) · `in-ticket` (`ap.py tickets`) · `done` / `placeholder` (`ap.py ticket … done [--placeholder]`) · `deferred` (you, with the spec's «Вне рамок» line, reaches the report) · **`dropped` — only the user, with their own words in Основание; you may only propose**. Silence never cancels. A fact «пришлю потом» keeps the row live. Implicit requirements `R##i` → briefing questions (full: `ASSUMPTION` decisions). `D##` — what the build proved; the only row you add after the briefing, via `phases/5-repair.md`, never retires a requirement, not counted.
4. Report one line: «Разобрал задачу на 23 требования — держу их под контролем до самого конца.» No table in chat.

**Gates (a failed gate redoes the phase):** G1 after briefing — every row has a status, `open` only with a named reason (full: none open) · G2 after spec — zero `open` + independent reader of brief+spec · G3 after plan — `ap.py check-plan`, both directions · G4 at the end — blind acceptance (`8-final.md`).

**Keeping current:** edit affected rows, never rewrite the table; mid-flight change → row moves (`dropped` with the quote, or new `G##`) **and the same words go into `## Дополнения`**.
