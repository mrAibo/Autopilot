# Phase 4 — Plan: Opus

Read from `4-plan.md`, only when `ap.py opus propose` lists candidate tickets.

- **Opus is the user's call, never the router's.** After `plan-models` (advisory) run `python3 .autopilot/ap.py opus propose` — it only prints the candidate tickets (marked `Модель: opus` or with a high risk score); it does not list roles. If the list is not empty, ask once, in the user's language: «Эти таски можно отдать Opus: 03, 05. Это дороже Sonnet-таска, не измерено — фактическая стоимость будет в отчёте по `measure-run.py`. Включить?» / "These tickets can go to Opus: … It costs more than a Sonnet ticket and is not measured; the actual cost lands in the report via `measure-run.py`. Enable?" A yes → `ap.py opus approve [--tickets 03,05] [--roles reviewer] --by-user "<цитата ответа>"`, then `plan-models --apply` again so the Opus profiles are registered (the approval is signed with the run's key and bound to this run: `slug|startedAt`; `opus status` shows «подпись: верна / НЕ СХОДИТСЯ / нет ключа»). Roles are used without further questions: the `repair` role — by `ticket F<n> route` for the branch fix ticket, the `reviewer` role — by `agent-for reviewer` for a branch diff over 3000 lines. No, or silence → nothing is written and every route stays as planned. Fable stays closed whatever the answer.
