# Вид `refactor` — поведение то же, тесты зелёные до и после

Ставится `init --kind refactor` или `ap.py set kind=refactor`.

1. До правок кода: `ap.py ticket NN baseline --command "<тесты>"`. Код ≠ 0 — отказ (тесты красные до рефакторинга — это не он); код 0 пишет `tk["baseline"]`. `ticket NN land` без `baseline` отказывает.
2. После правок `land` сам гоняет полную проверку (как обычно): зелёная до и зелёная после.
3. Существующие (отслеживаемые git) тесты править нельзя: если среди изменённых файлов такой есть, а в файле таска нет строки `**Правка тестов:** <причина>`, `land` отказывает. Новые тестовые файлы можно. `check-plan` тоже отказывает, если зона таска в тестах и такой строки нет.
4. Исключение `**Правка тестов:**` — только записанное планировщиком в файле таска. Ревью ветки **обязано подтвердить каждое** такое исключение: открыть дифф теста и написать в отчёте «исключение подтверждено» или «не подтверждено: <почему>»; не подтверждённое — блокирующее замечание.
5. `--by-user` отказы `refactor` не снимает.
