# Бриф — Autopilot: правки по итогам сборки «Темы дашборда» и свежему Claude Code

Дата: 2026-11-05
Основа: `ROADMAP-claude-code-2026-11.md` (черновик), проверка по коду и по claude.com (раздел 6).
Требование из этого брифа может снять только пользователь.

## 1. Цель

Убрать дефекты процесса, которые стоили времени в последней сборке (потеря статусов тасков, сметённый индекс, пути машины в файлах прогона), и подогнать Autopilot под изменения Claude Code (советник, возобновление после лимита, версия, моды). Поведение шлюзов G1–G4 и независимой приёмки не ослабляется.

## 2. Требования и критерии приёмки

### Волна 1 — снимают риск, маленькие

**R01. Отпечаток таска не зависит от окончаний строк** (A01)
- Корень: `skills/autopilot/tools/ap.py:420` считает sha256 по сырым байтам файла; сравнение — `ap.py:422` и `ap.py:1375`.
- Отпечаток считается по нормализованному тексту: LF, без хвостовых пробелов, без BOM.
- Совместимость: у уже опубликованных тасков в `state.js` лежит старый отпечаток по сырым байтам. Совпадение с любым из двух (старый или новый) = таск не менялся, отпечаток молча переписывается на новый. Иначе первый запуск после обновления сбросит все сданные таски.
- Смена смысла у сданного таска не сбрасывает его молча: останов с сообщением и командой `ticket NN accept-edit --note "..."`.
- Тесты: CRLF↔LF не меняет статус; старый отпечаток принимается и мигрирует; правка смысла сданного таска останавливает, а не сбрасывает.

**R02. Исполнители не трогают чужой индекс** (A03)
- `skills/autopilot/prompts/executor.md` и профили: запрещены `git stash`, `git reset`, `git checkout -- <чужие пути>`; коммит только `git commit --only <файлы зоны>`; перед коммитом `git diff --cached --stat`.
- `claude_agent_guard.py` отклоняет `git stash` в Bash-вызовах субагентов строгого прогона (сейчас `stash` в нём не упоминается).
- Тесты: хук отклоняет `git stash`, `git stash pop`, `git reset --hard`; обычный `git commit --only` проходит.

**R03. В файлы прогона не попадают пути машины** (A04)
- `phases/4-plan.md` и промпты: образцы — через `<scratchpad>` и `<repo>`.
- Проверка при публикации тасков и спецификации (`ap.py`): абсолютный путь пользователя (шаблоны из `tests/test_no_machine_data.py`) = отказ с указанием файла и строки. Ловим за секунды, а не после 5-минутного прогона.
- Тест: таск с `C:\Users\<имя>\...` не публикуется; плейсхолдеры проходят.

**R04. Политика для `/advisor`** (C01)
- Сейчас в коде и фазах советника нет совсем. Описать в `docs/autopilot/claude-code.md` и `model-routing.md`: советник — серверный инструмент, субагенты наследуют настройку `advisorModel`, `is_allowed_subagent_model` его не видит.
- `phases/0-preflight.md`: в строгом прогоне предупредить, если `advisorModel` настроен; предложить `CLAUDE_CODE_DISABLE_ADVISOR_TOOL=1` на время сборки.
- Открытый вопрос (решить живой проверкой, записать итог): видны ли вызовы советника в `attestations.jsonl` (`models_used`).
- Тест: документация содержит правило и оговорки.

**R05. Возобновление после лимита** (C02)
- `phases/0-resume.md` и `phases/5-repair.md`: исполнитель упал на лимите → `git status` и `git diff` его зоны → `SendMessage` тому же агенту «продолжи», нового не заводить; пункт про незакоммиченные правки зоны.
- Добавка: в сообщение пользователю — время сброса лимита (5-часовое окно и недельное у плана); для Ultra 5-часового лимита нет.

**R06. Проверка версии Claude Code** (C03, смягчено)
- `0-preflight.md`: `claude --version` до `init`, разбор строки версии, тест на разбор.
- Жёсткий минимум остаётся 2.1.295 (на нём стоят `onFailure` и effort на вызов). Версии ниже 2.1.311 — предупреждение с перечнем известных проблем, но не отказ: у владельца стоит 2.1.302, и настольное приложение приносит собственную версию.

### Волна 2

**R07. План-модели в переоткрытом прогоне** (A02): `plan-models --apply` работает для новых pending-тасков при сданных; новые профили регистрируются с явным стопом «новый чат». Тест: два сданных и один новый таск.

**R08. Шлюзы не сбрасываются на оформление** (A06): использовать ту же нормализацию, что в R01. Различать «контракт» (состав и смысл) и «оформление» (пробелы, пути, окончания строк); на оформление G1/G2/G4 не сбрасываются. Тест: правка пробелов/пути не сбрасывает шлюз; правка текста требования сбрасывает.

**R09. `dashboard_upgrade.py` из `.autopilot/`** (A07): либо понятное сообщение «запусти из каталога навыка», либо поиск шаблона по `skillDir` из `state.js`. Тест на оба случая.

**R10. Effort субагентов** (C04): проверить на живом сеансе место `CLAUDE_CODE_SUBAGENT_EFFORT` в порядке приоритетов, обновить таблицу в `claude-code.md`, согласовать с `agent_profiles.py`.

**R11. Долгие тесты** (C05): `prompts/executor.md` — полный прогон через `run_in_background` с явным ожиданием результата; «команда ушла в фон» ≠ «тесты зелёные».

**R12. Гигиена хуков** (C06): тесты на поведение `claude_agent_guard.py` и `claude_attest.py` (без живого Claude Code, где можно); в `claude-code.md` перечислить проверенные поведения и версию.

**R13. Модельная политика** (C12, поправлено): `is_premium_model` на новые написания (`claude-fable-5-1`, `claude-opus-5-5`, `claude-sonnet-5-5`, `claude-haiku-5-5`), тесты. Быстрый режим теперь у Opus 5.5 (claude.com: исследовательский просмотр, 8 $/40 $ за млн токенов), а не у Opus 4.8: убрать из документации устаревшее.

**R22. Журнал прогона по умолчанию** (новое, первым в волне 2: по нему проверяются R23–R27)
- `.autopilot/run-log.jsonl`, одна строка на событие: начало и конец фазы (время); таск (старт, повтор, причина падения, результат шлюза); число и длительность запусков тестов; каждый сброс статуса или шлюза с причиной; исполнитель (профиль, число ходов, токены).
- Токены берутся автоматически из транскриптов субагентов (`transcript_path` уже пишет `claude_attest.py`), а не вручную через `ap.py usage`.
- Только метаданные: без промптов, содержимого файлов, путей машины. На журнал распространяется проверка вида `test_no_machine_data`.
- Журнал только пишет и никогда не блокирует работу; лежит вне подписанного состояния, не влияет на отпечатки и шлюзы; ротация по размеру.
- `ap.py report-run` сворачивает журнал в таблицу: фазы, таски, повторы, простои, токены. `report-run --share` даёт сводку без данных проекта для приложения к issue.
- Тесты: журнал пишется на каждом событии; сбой записи не ломает прогон; в журнале нет пути машины и текста промптов; сброс статуса попадает в журнал с причиной.

**R22a. Дыры хука `git` из волны 1** (`claude_agent_guard.py`, берётся в тот же запуск, что и R22)
- Хук отклоняет также `git.exe stash`, `/usr/bin/git stash`, `bash -c "git stash"`, `git restore .`, `git checkout .`, `git clean -fd` (по границам команды вне кавычек, как уже сделано для `git stash`).
- Тесты: каждая форма отклоняется; `git commit --only`, `git status`, `git diff` проходят; слово `stash` в кавычках и в сообщении коммита не срабатывает.

**R22b. Сбой Bash-хука**: описать в `docs/autopilot/claude-code.md`, что `onFailure: block` на хуке `Bash` при его сбое блокирует все Bash-команды проекта, и как это снять (удалить запись из `.claude/settings.json`). Менять поведение хука только по решению владельца.

**R22c. `accept-edit` и worktree**: сданный таск после `accept-edit` с неосвобождённым worktree не проходит публикацию (`ap.py:454`): отказ с указанием, что worktree надо посадить или снять. Тест на этот случай; тест `test_changed_ticket_resets_previous_acceptance` переименовать по тому, что он проверяет на самом деле.

**R23. Выборочные тесты на таск** (после R22): исполнитель гоняет тесты своей зоны, полный прогон остаётся обязательным на шлюзе и в `finish`. Включать только если по журналу видно, что полный прогон съедает заметную долю времени; сравнивать на 3+ прогонах.

**R24. Пакет таска без лишнего** (после R22): проверить, что получает исполнитель; цель — файлы зоны и интерфейсы вместо всей спецификации. По журналу сравнить токены до и после.

**R25. Стабильное начало промптов исполнителей** (после R22): общие правила и интерфейсы в начале, одинаковые у всех исполнителей, чтобы попадать в кэш промпта. Эффект неизвестен, мерить.

**R26. Модель для проверяющих** (после R22): сравнить стоимость и качество находок при уровне ниже для механических проверок. Менять политику только по данным.

**R27. Сквозной тест «переоткрытие»** (A01–A04 одним сценарием): `reopen` → правка тасков с CRLF → исполнитель со `stash` → публикация тасков с путём машины; тест должен поймать все четыре. Плюс команда проверки состояния только для чтения: расхождения отпечатков, индекса и статусов до того, как что-то сбросится.
